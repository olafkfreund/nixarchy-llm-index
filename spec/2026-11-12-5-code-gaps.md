# Spec: close three code gaps found while documenting v0.1

## Design

### 1. Unsafe path names are never indexed

A path name is **unsafe** if any character is one `sanitize` strips
(`src/sanitize.rs` `is_stripped`), is a control character
(`char::is_control`: C0, DEL, C1, which covers newline, tab and ESC), or the
name is not valid UTF-8.

- **Scan and watch:** `src/worker/scan.rs` `Walker::reason` returns
  `Some("unsafe_name")` when the entry's own name is unsafe. It is checked
  first, before the other reasons. The scan walk stops recursing on any
  reason (`scan.rs` around line 425), live watcher events call `reason`
  before adding a watch (`src/worker/watch.rs` around line 205), and
  `allowed_event` also checks each relative component, so an unsafe
  directory is skipped with its whole subtree, like a denylisted one.
  `walk_subtree` trusts its starting directory; it is only started from
  directories that already passed `reason`, which a watcher test proves. One new helper
  `sanitize::unsafe_name(&OsStr) -> bool` holds the rule; it sits next to
  `is_stripped` so the two rules cannot drift apart.
- **Existing rows:** a file indexed before this change is not seen by the
  next *complete* scan, so `apply_scan` (`src/index/store.rs` around line
  509) deletes it. `unsafe_name` is not one of the reasons `protects`
  keeps, so its old descendants go too. No schema change and no forced
  reindex.
- **MCP, fail closed:** until that scan, and as a second layer, the three
  places that emit a stored *file* path (`hit()` for `search`, `recent`, and
  `get`'s echo, `src/mcp.rs` around lines 321, 475 and 510) drop any row
  whose path contains an unsafe character. `get` on such a path answers
  "not found". The JSON stays as it is for every safe path, so `get` still
  round-trips every path a tool returned.
- **Config:** `Config::validate` (`src/config.rs`) rejects a root path,
  exclusion path or `state_dir` with an unsafe character, with the fixed
  message `path contains control or invisible characters`, which does not
  include the path. This check runs **first**, before every other check that
  puts a path into its error (duplicate root, invalid root, invalid
  exclusion), so no error text can carry an unsafe path. With configured
  paths safe, the other path-bearing output is safe too: `status` prints
  only configured root paths and `config_errors` paths, which are configured
  roots and exclusions, and the private server's error text only quotes
  config errors. `nix/config.nix`
  assertions get the same rule (the modules must keep mirroring the parser):
  reject a root, exclusion or `stateDir` path that `builtins.match` finds
  containing a C0 control character or DEL (`stateDir` gains its first
  assertion). Nix strings cannot easily test every Unicode class, so
  the Rust check stays the authority and the plan records the narrower Nix
  rule.

Not counted in `status`. A new counter would need a schema change, and
denylisted files are not counted either. The skip is logged once per entry
at debug level, as the other reasons are.

### 2. `maxCells` for ODS and XLS

In `src/extract/sheet.rs`, the ODS and XLS branches keep a running
`total_workbook_cells`. After each `worksheet_range` call they add
`range.height() as u64 * range.width() as u64` (saturating; the full
rectangle, empty cells included) and return
`ExtractError::TooLarge` once the total exceeds `limits.max_cells`, before
`append_range_segments`. This uses the same error and the same counting rule
(the full rectangle) as XLSX.

Known residual, stated plainly: calamine 0.38 loads **all** ODS and XLS
sheets when the workbook is opened (`Ods::new` / `Xls::new`), before the
first check can run. The new budget therefore stops what happens after
loading (segmenting, chunking, embedding), not the initial allocation. A
small sparse or compressed workbook can still allocate a large dense range
at open. The fixed 20 MiB input cap and the worker's `RLIMIT_AS` (4 GiB)
bound it; an abort is contained by the worker process, as for the other
residual parser aborts. The docs say this.

### 3. Unknown MCP arguments are rejected

Add `#[serde(deny_unknown_fields)]` to `SearchArgs`, `GetArgs` and
`RecentArgs` in `src/mcp.rs`, and give `status` an empty
`StatusArgs {}` with the same attribute, taken as `Parameters<StatusArgs>`.
Omitted arguments and `{}` stay valid for `status`; any key fails. The schemas in `tools/list` then carry
`additionalProperties: false`, which schemars emits for `deny_unknown_fields`.
An unknown name fails the call as invalid parameters, with serde's
`unknown field `foler`, expected one of …` text. The plan step confirms
on the wire, with the rmcp 3.9.0 in `Cargo.lock`, that the error reaches the
client as invalid params with that text, that `status` still accepts an
omitted `arguments`, and that `tools/list` shows `additionalProperties:
false`. If rmcp turns an omitted `arguments` into an error for
`Parameters<StatusArgs>`, the plan records the workaround.

### Docs

The same PR updates `docs/reference.md` (unsafe paths never returned;
unknown arguments rejected; `maxCells` for all three formats),
`docs/security.md` (path rule), `docs/troubleshooting.md` ("a file with an
odd name is not found"), `docs/installation.md` (`maxCells` row; root path
rule) and `share/AGENTS.snippet.md` only if a signature changes (none
does).

## Alternatives rejected

- **Return a sanitized path.** It breaks `get`: the cleaned path no longer
  names the file, and two files could clean to the same name.
- **Escape unsafe characters visibly (for example `\u{202e}`) and decode
  in `get`.** Reversible, but it adds an encoding every client must
  understand and that agents can be tricked by. Such names are rare;
  skipping them is simpler and fails closed.
- **Filter only in MCP and keep indexing the files.** The passage text
  would still be stored and counted, and a bug in one emit path would leak
  the name. Filtering at scan time removes them at the source.
- **A real streaming ODS/XLS reader.** Not available in calamine; writing
  one is out of scope.
- **Count unsafe names in `status`.** Needs a schema change for little
  value; denylisted files are not counted either.

## Risks

- Users with legitimate filenames containing control or bidi characters
  (rare, for example RTL users with bidi marks in names) lose those files
  from the index. The troubleshooting page says how to recognise this.
- `deny_unknown_fields` could break a client that sends extra fields (for
  example a `_meta` key inside arguments). The MCP spec puts `_meta` beside
  `arguments`, not inside it; the plan checks the rmcp request path to
  confirm.
- No host is touched. Rollback is a revert.

## Verification

1. Unit tests:
   - `unsafe_name` true for RLO, a tag character, a zero-width space,
     newline, ESC, DEL, a C1 control and invalid UTF-8; false for ordinary
     names, including non-Latin ones.
   - `Walker::reason` returns `unsafe_name` for such a file and directory.
   - Watcher: a newly created unsafe directory holding a safely named file
     produces no event for that file.
   - A file indexed before the change (unsafe name) is deleted by the next
     complete scan.
   - The MCP emit filter drops an unsafe stored path from `search`,
     `recent` and `get`.
   - `Config::validate` rejects an unsafe root, exclusion and `state_dir`,
     including two duplicate unsafe roots (the unsafe error wins and the
     message has no path).
   - The private MCP server's error for an unsafe config contains no path.
   - An ODS and an XLS fixture above a small `max_cells` give `TooLarge`;
     below it, they extract as before; a multi-sheet workbook where each
     sheet fits but the sum exceeds the budget gives `TooLarge`.
   - `search` with `foler` fails naming the field; `search` with only
     known fields is unchanged; `status` with `{"x":1}` fails, with `{}`
     or no arguments works; a request with `_meta` beside `arguments`
     works.
2. Integration: `tests/mcp.rs` gets one case per tool for an unknown
   argument; `tests/e2e.rs` (or the fixture check) indexes a tree with an
   RLO-named file and asserts it is absent from `search` and `recent`.
3. `nix/checks/modules.nix` gets failing cases for a root, an exclusion
   and a `stateDir` with a control character.
4. `cargo test --all-features`, `cargo clippy --all-targets --all-features
   -- -D warnings`, full `nix flake check`.
5. Codex review of the diff, read-only.
