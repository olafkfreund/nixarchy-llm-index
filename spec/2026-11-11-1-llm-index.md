# Spec: nixarchy-llm-index v0.1

Scope is v0.1 from the approved intent. v0.2 items appear only where v0.1
must leave room for them.

## Design

### Shape

One Rust binary, `llm-index`, with four subcommands, plus Nix modules that
run and register it.

```text
                        config.toml (generated by the module)
                                   │
  ┌────────────── llm-index index (one per owner, systemd service) ──────────┐
  │ coordinator: roots, schedule, queue, tier routing, purge                │
  │   ├─ local watcher (inotify, one watch per directory)                   │
  │   ├─ poll scheduler for network roots                                   │
  │   └─ worker pool: `llm-index worker` child processes (scan + extract)   │
  │ writes: public.db, private.db  (SQLite: FTS5 + int8 vector column)      │
  └─────────────────────────────────────────────────────────────────────────┘
        ▲ reads only                                   ▲ reads only
  llm-index mcp --tier public                   llm-index mcp --tier private
  (stdio, spawned by a cloud client)            (stdio, spawned by a granted
   opens public.db only                          local-only client; opens both)

  llm-index status   — roots, freshness, offline shares, sizes
```

| Subcommand | Runs as | Purpose |
| --- | --- | --- |
| `index` | long-running service | the only writer; schedules work, owns the databases |
| `worker` | child of `index`, short-lived | lists one root or extracts one file; may block or crash without harm |
| `mcp` | spawned per client session over stdio | read-only search and read tools |
| `status` | CLI | human and script view of index health |

### Why Rust

Both research rounds (Claude, Codex, agy) agreed: a single native binary
meets the closure and memory bounds; the crates needed exist and are
permissively licensed; Python needs a larger closure and slower cold start for
a stdio server spawned per session; Go needs CGo for SQLite, tree-sitter and
PDF anyway.

No GPU, ML framework, ONNX runtime, Ollama, database server or network
service. pdfium is the only large native library; it is BSD-licensed, in
nixpkgs and used by both research candidates.

### Storage and tiers

- State lives in `$XDG_STATE_HOME/llm-index/` (user service; created by
  `index` itself) or `/var/lib/llm-index/<owner>/` (system service,
  `StateDirectory=`), mode `0700`, files `0600`; option `stateDir`
  overrides it. `index` refuses to start when the state directory is on a
  network or FUSE filesystem (`statfs`) or has a parent holding a
  sync-folder marker (`.stfolder`, `.sync`, `.dropbox`,
  `.nextcloudsync.log`, `.sync_*.db`). The state directory is a built-in
  exclusion, so a root such as `$HOME` that contains it never indexes it.
  `CACHEDIR.TAG` is written for backup tools. Scope of "kept out of file
  sync by default": the default location is not one that Syncthing,
  Nextcloud or Dropbox sync unless the user chooses it, and a location under
  one of their folder markers is refused. A sync the user sets up for all of
  `$HOME` or `$XDG_STATE_HOME` is outside the project's control; the README
  says to exclude the directory.
- **Two databases**: `public.db` and `private.db`, same schema. A document
  lives in exactly one. Tier separation is a process boundary: `mcp --tier
  public` opens only `public.db` and has no flag, path or tool that reaches
  `private.db`. `mcp --tier private` opens both and runs each search leg
  per database; meaning hits merge by similarity (same model, comparable),
  and the two words lists (whose BM25 statistics differ per database) enter
  reciprocal rank fusion as separate lists.
- Schema (per database): `roots(name, path, kind, share_id, state,
  reason, last_scan, queued, done, skipped_symlinks)` (the coordinator keeps
  this current; `status` reads it, so no socket is needed), `files(root_id, relpath, abspath, title, type, size, mtime_ns,
  blake3, state)`, `chunks(file_id, ord, kind, start, end, decl_start,
  decl_end, heading_or_symbol, text, vec)`, `chunks_fts` (FTS5 over chunk
  text), `files_fts` (FTS5 over title and path), `embed_cache(input_blake3,
  vector)`, `meta(model_rev, schema_version)`. Both FTS tables use the
  `unicode61` tokenizer with diacritics folded and **no stemming**.
- File identity is `(root_id, relpath)`; `root_id` is the configured root
  name, never device or inode numbers. `abspath` is the root path plus
  `relpath`, kept so authorization can re-derive the current root (see
  Authorization). Content identity is BLAKE3.
- **Root paths are canonical.** A configured root must be an absolute path
  with no symlink in any component. Each scan worker acquires its root with
  `openat2(AT_FDCWD, path, O_PATH | O_DIRECTORY, RESOLVE_NO_SYMLINKS |
  RESOLVE_NO_MAGICLINKS)`, which fails on a symlink in any component, so the
  check and the acquisition are one atomic step and the fd it scans is the
  directory the path names. `ELOOP` makes the root `config_error`;
  `ENOENT` or a dead mount makes it `offline`, never `config_error`. Files are
  then opened beneath that fd without following symlinks, so `root path +
  relpath` is the file's real path, and authorization can work on strings
  alone (below).
- **Nested roots:** a parent root's walk skips any directory that is another
  configured root, so every file belongs to exactly one root.
- The embed cache key is BLAKE3 of the full embedding input (path and symbol
  prefix plus text) and the model revision. A moved file is re-embedded; an
  unchanged file is not.
- Vectors are L2-normalised (the model's `normalize: true`), multiplied by
  127, rounded and clamped to `int8`, and stored as a plain 512-byte BLOB
  column of `chunks` (about 50 MB per 100,000 chunks). Similarity is the
  int8 dot product, computed by a Rust scalar function registered with
  `rusqlite`. No `sqlite-vec`, no `vec0`: see Search.
- **Titles** are extracted per file: Markdown front-matter `title` or first
  H1; HTML `<title>`; PDF `Title` metadata, else the first text line; `.docx`
  / `.odt` `dc:title`, else the first heading; spreadsheets and code: the
  filename.

### Search

`search(query, mode?, field?, folder?, type?, after?, before?, limit?)`:

- `mode`: `hybrid` (default), `words` or `meaning`.
- `field`: `any` (default), `title` or `path`. `title` and `path` search
  `files_fts` only and return one hit per file.
- **Words** means whole tokens, case- and diacritic-insensitive, no stemming;
  `"quoted text"` is a phrase. Morphological variants are the meaning
  search's job.

1. Eligible files: the SQL filters (`folder` as a path prefix, `type`,
   `after` / `before` on file mtime) joined with the authorization set (see
   below). Both apply before any ranking, for both legs.
2. Words: FTS5 BM25 over `chunks_fts` and `files_fts`, eligible files only.
3. Meaning: embed and quantise the query; `ORDER BY dot_i8(vec, ?) DESC`
   (higher is more similar) over the `vec` column of eligible chunks,
   `LIMIT`. This is an exact scan, so a selective filter never loses
   the nearest eligible chunk. At 300,000 chunks the scan reads about 150 MB
   from page cache.
4. Fuse with reciprocal rank fusion (k = 60).
5. Each hit returns `path`, `title`, `mtime`, `type`, `tier` (private server
   only), `stale`, `lines` (code: the whole declaration, `decl_start`–
   `decl_end`) or `page` or `sheet` and rows, `symbol` or `heading`, and a
   preview passage of at most 800 characters (for `title` / `path` hits: the
   file's first chunk). The full text comes from `get`.

Other tools: `get(path, start?, end?, sheet?)` reads indexed text of one
document: `start` / `end` are pages for PDF, rows for spreadsheets (with
`sheet`), and lines of the extracted text for everything else (for code the
indexed text is the original source, so a hit's `lines` returns the whole
function). One call returns at most 20,000 characters and a `next` range
when there is more; `recent(days, folder?, type?)`
lists changed files; `status()` shows roots and freshness. All tools are
read-only (`readOnlyHint`). Every passage is wrapped as untrusted document
content with its path, and Unicode tag, bidi-override and zero-width
characters are stripped at ingest.

**Model memory.** `mcp` never loads the 129 MB embedding matrix. It parses
the safetensors header once and `pread`s the 2 KB row of each query token
from the store file, so its RSS is SQLite caches, the tokenizer (about 5 MB)
and a few KB per query, idle or warm; repeated rows come from the kernel
page cache, which is not process memory. No load/unload timer. `index`
memory-maps the matrix (bulk embedding touches most of it, inside its 1 GB
budget).

### Authorization (both servers, every tool)

One function, `visible(abspath) -> tier | none`, decides every row any tool
returns: `search`, `get`, `recent` and `status` alike.

- It recomputes from the **current** `config.toml`, on strings only, never
  touching a filesystem: the longest configured root whose path is a
  component-wise prefix of `abspath` gives the tier; no matching root gives
  `none`; a match on a user exclusion or the built-in denylist (with lifts
  only for private roots) gives `none`; a root whose stored state is
  `config_error` gives `none`. The stored `root_id` and database are never
  trusted on their own, so a private child root added under a public root, a
  removed root, a changed root path or a new exclusion all take effect
  without the indexer, and while the share is unmounted or dead: nothing is
  resolved, so nothing can block.
- **New paths are validated before the public tier trusts them.** String
  matching is exact only for canonical paths, and a root or exclusion written
  through a symlink would silently not match. So the indexer records in
  `public.db` the set of root and exclusion paths it has validated (each
  acquired with `openat2(..., RESOLVE_NO_SYMLINKS)` in a worker under the
  share rules). While `config.toml` names a root or exclusion that is not in
  that set, every public tool fails closed with `config change pending
  validation: <path>`. Removing a root or changing a tier to private needs no
  validation (it only shrinks the public set) and applies at once. A path
  that fails validation (`ELOOP`) keeps the public tier closed and shows in
  `status` until the user fixes it. A path on a dead share stays pending, so
  the public tier stays closed until the share returns or the change is
  reverted: a deliberate trade of availability for no disclosure. The private
  server applies new rules by string at once and never closes.
- Exclusions must lie at or under a configured root (an exclusion elsewhere
  can only be a symlink alias); config with one is invalid.
- The public server returns a row only when `visible` is `public`. `status`
  on the public server lists only public roots; private root names, paths and
  counts never appear.
- `visible` is a Rust scalar SQL function used in the `WHERE` clause of
  every query, so rows the indexer adds later are judged like any other; each
  tool call runs in one read transaction (one WAL snapshot). The server
  re-reads `config.toml` when its mtime or inode changes. Missing,
  unreadable or invalid config makes every tool return an error: fail
  closed, never fall back to the last good config.
- The indexer purges the same rows at its next pass. Until then the filter
  alone hides them, mounted share or not.

### Indexing

- **Discovery** uses the `ignore` walker: `.gitignore`, `.git/info/exclude`,
  global gitignore, plus `.llmindexignore`, the built-in denylist and user
  excludes. Git is never executed: running `git` inside an untrusted
  repository can execute its configuration (`core.fsmonitor`, hooks), which
  the threat model forbids.
- **Format dispatch first.** The extractor is chosen by extension and
  confirmed by magic bytes (`%PDF-`; ZIP with the expected
  `[Content_Types].xml` or `mimetype` member for `.docx`, `.xlsx`, `.odt`,
  `.ods`; OLE2 `D0 CF 11 E0` for `.xls`). `.csv` goes to the CSV reader after
  the text checks. Office and PDF files never go
  through the text heuristics below. A file whose magic does not match its
  extension is skipped as `mismatch`.
- **Skipped by default:** `.git/`, `node_modules/`, `vendor/`,
  `third_party/`, `target/`, `.venv/`, `venv/`, `__pycache__/`, `.direnv/`,
  `result*`, directories with `CACHEDIR.TAG`, lockfiles, files over 50 MB.
  For plain-text and code files only: binary (NUL in the first 8 KB or not
  valid UTF-8), minified (`.js`, `.css`, `.json`, `.map` with average line
  length over 250), and generated (`@generated` or `Code generated … DO NOT
  EDIT` in the first 4 KB). HTML and documents
  are never dropped as minified.
- **Built-in denylist** (all tiers; liftable for private roots only):
  `.env*`, `*.pem`, `*.key`, `id_rsa*`, `id_dsa*`, `id_ecdsa*`,
  `id_ed25519*`, `*.p12`, `*.pfx`, `*.kdbx`, `*.age`,
  `.netrc`, `.git-credentials`, `.npmrc`, `.pypirc`, `.docker/config.json`,
  `.cargo/credentials*`, `.ssh/`, `.gnupg/`, `.password-store/`, `.aws/`,
  `.azure/`, `.kube/`, `.config/gcloud/`, `.config/gh/`, `.config/sops/`,
  `.local/share/keyrings/`, `.claude/`, `.codex/`, `.gemini/`,
  `.antigravity/`, `.config/Antigravity/`, `.mozilla/`, `.thunderbird/`,
  `.config/google-chrome/`, `.config/chromium/`,
  `.config/BraveSoftware/`, `.config/vivaldi/`, and everything under
  `/run/` (covers `/run/agenix`, `/run/secrets` and the per-user
  `$XDG_RUNTIME_DIR/agenix` and `secrets` of Home Manager agenix and
  sops-nix), `/proc/` and `/sys/`.
  Matching is the project's own, not gitignore: case-insensitive, against
  the **absolute path** of each file. A pattern starting with `/` is anchored
  at the filesystem root. Every other pattern, with or without inner `/`
  (`.config/gcloud/`), matches any run of path components at any depth, as
  if prefixed with `**/`. A trailing `/` denies the directory and everything
  under it. So a root that starts inside a denied directory is denied
  whole. `lift_builtin` entries apply
  only while the file's current root is private.
- **Symlinks** are never followed. The walker runs with `follow_links(false)`
  and `same_file_system(true)`; a symlink is skipped and counted in `status`.
  Mounts inside a root are not crossed; mount them as their own root.
- **Open-time containment.** A configured root is checked canonical and
  opened as a directory fd in its worker. Every file is opened with `openat2(root_fd, relpath,
  RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS |
  RESOLVE_NO_XDEV)` and `O_RDONLY | O_NOFOLLOW`, then `fstat` must show a
  regular file. A file or intermediate directory swapped for a symlink
  between listing and reading fails the open; nothing outside the root is
  read under the root's tier. Exclusion and denylist checks run on the
  absolute path before the open. Validated paths (above) are what
  exclusions are matched against.
- **Chunking:** code by tree-sitter declarations, packing small siblings up to
  about 512 tokens; a declaration larger than that is split, and every part
  records the declaration's full line range (`decl_start`, `decl_end`). The
  stored text is the original source; the path and enclosing symbol are a
  prefix of the embedding input only. Markdown by headings; other text by
  `text-splitter`; PDF by page; spreadsheets by sheet and row block.
- **Tier routing:** the longest matching root wins; a root's tier is
  `public` or `private` (default `private`). Moving a file across tiers
  deletes it from one database and inserts it into the other in one
  coordinator transaction per database, public delete first.

### Workers and network roots

- The coordinator never touches a root. Every scan, `statx`, file read,
  `statfs`, root acquisition and inotify watch happens in a `worker` child
  process, talking JSON lines over a pipe.
- **Watcher workers.** Each local root has one long-lived watcher worker
  (outside the pool). It walks the root's directories and adds a watch on
  each with `IN_ONLYDIR | IN_DONT_FOLLOW`, skipping any directory that
  `mountinfo` lists as a mount point strictly below the root's own containing
  mount (those are not part of the root), and forwards events. The 30-second
  progress rule applies while it is adding watches; if it trips, the root is
  `degraded` and polled (below), and the share rules apply to that worker.
- The coordinator `poll`s `/proc/self/mountinfo` for changes (the kernel
  signals a mount table change); on a change it re-derives share identities
  and queues a scan of every root whose containing mount changed.
- Each worker, in this order: opens `/proc/self/mountinfo` and the global
  gitignore and keeps the fds; sets `oom_score_adj` to 1000 and `RLIMIT_AS` to
  4 GB (a runaway guard on virtual memory only; the real memory cap is the
  service cgroup, see Resource controls); opens its root (in a worker, so a
  dead mount blocks only it); then applies a **Landlock** ruleset that
  handles read and write access: read-only beneath its root fd and the store,
  no write anywhere, and (Landlock ABI 4+) no TCP bind or connect. Only then
  does it take a job. Mount checks re-read the kept `mountinfo` fd from
  offset 0. Workers have
  a per-job timeout (scan: 10 minutes, extract: 30 seconds) and a
  decompression guard (zip members: total uncompressed size at most 100 times
  the archive and at most 500 MB). A worker that exceeds a limit marks its
  file `failed` with the reason. A worker OOM-killed while another worker was
  running gets one retry with the pool to itself; failing that, or failing
  alone, the file is `failed`. A failed file is retried only when its size or
  mtime changes.
- **Share identity.** A *share* is the backing source of the mount that
  contains a root: `(fstype, source, mount root)` from `/proc/self/mountinfo`,
  for example `nfs4 nas:/export /`, plus the mount point. The coordinator
  derives it **before any
  I/O on the root**, by string match of the root path against mount points in
  `mountinfo` (reading `mountinfo` asks the kernel's mount table and never
  touches a filesystem). So every root has a scheduling identity at startup,
  even on a dead mount, and the one-worker-per-share rule applies from the
  first probe. Several roots on one share (for example two subdirectories of
  it) share one identity. Root kind (`local` or `network`) follows from the
  fstype: NFS, CIFS/SMB2, FUSE (incl. `fuse.sshfs`, `fuse.rclone`) and
  `autofs` (an untriggered automount, whose target is unknown until opened)
  are `network`; overridable per root.
- **Expected identity** is set with `share = "nas:/export"` (recommended for
  network roots) or recorded at the first successful scan. When the
  containing mount is `autofs` (`x-systemd.automount`), the worker opens the
  root, which triggers the mount, and the identity is read again. If the
  share was not mounted at the first scan, the recorded identity is the
  local parent filesystem. A later network mount at a **deeper** mount point
  replaces it only while no scan of that root on a network filesystem has
  ever succeeded (the share has appeared for the first time); after that,
  any change of source, mount point or depth is a mismatch, so mounting
  something over part of an indexed share never deletes its entries.
- **Local roots:** inotify events, debounced 2 seconds, plus a full
  reconciliation pass daily. If a watch cannot be added (`ENOSPC`, watch
  limit), the queue overflows (`IN_Q_OVERFLOW`) or the watcher fails, the
  root switches to `degraded`: an immediate reconciliation scan, then polling
  every 2 minutes until watching succeeds again. `status` shows the reason.
- **Network roots:** polled every `interval` (default 15 minutes) by a scan
  worker that lists `(relpath, size, mtime_ns)` using `statx` with the
  default sync mode (no `AT_STATX_DONT_SYNC`). The project never changes mount
  options, so a remote edit is seen by the first scan after the client's
  attribute cache for that file expires (NFS `acregmax`, default 60 seconds;
  sshfs and rclone have their own cache settings): at worst `interval` plus
  that period. `status` shows each root's `last_scan`. Changed entries are
  queued for extraction on that share.
- **Mount check.** Before a scan, and again after it completes, the worker
  compares the containing mount's identity, and the root fd's `st_dev`, with
  the expected identity. Unmounted (the containing mount is now the parent
  filesystem), a different share mounted at the same place, or a change
  during the scan: the root is `offline (identity mismatch)` and the scan
  result is discarded.
- **One live worker per share.** At most one worker process (scan or
  extract) exists per share at any time, counting a worker until `waitpid`
  has reaped it, not until it was signalled. A worker that reports no
  progress for 30 seconds (progress = entries listed or bytes read, sent by
  the thread doing the I/O, never a timer thread) is sent `SIGKILL` and
  *abandoned*: the share is `offline`, and nothing new starts on it until
  that process has exited **and** backoff (doubling from 1 to 60 minutes) has
  expired. A worker stuck in uninterruptible sleep therefore blocks only its
  own share, forever if need be, and there is never a second one.
- **Pool capacity.** The pool (`workers`, default 2, minimum 2, enforced by
  the module and at start) counts only live, non-abandoned workers, and
  network jobs may hold at most `workers - 1` slots, so local roots always
  keep one. An abandoned worker leaves the pool within 30 seconds.
- **Task budget.** Workers are single-threaded. Abandoned workers are at
  most one per share, so at most the number of network roots. The module
  sets `TasksMax` = coordinator threads (fixed, at most 16) + `workers` +
  local roots (watchers) + network roots + 8, so stuck workers on every share
  at once can never take the tasks a healthy worker needs, and every healthy
  share keeps being scanned.
- **Deletion only after a complete scan.** A file disappears from the index
  only when a scan of its root finished, passed both mount checks, and did
  not list it. Partial, failed, offline or mismatched scans never delete.
  Entries of an offline root are served with `stale: true`.

### Resource controls

The module sets on the `index` service: `Nice=19`,
`IOSchedulingClass=idle`, `CPUWeight=20`, `MemoryHigh=768M`, `MemoryMax=1G`
(option, `limits.memory_max_mb`), `OOMPolicy=continue`, `TasksMax` as
computed above, and a worker pool of 2 (option). `MemoryMax` caps the coordinator and all workers together. Workers
have `oom_score_adj=1000` and the coordinator keeps 0, so when the cgroup
hits its cap the kernel kills a worker, and `OOMPolicy=continue` keeps
systemd from stopping the service; the retry rule above applies.
`mcp` is spawned by the client and inherits its limits. Battery pause is
v0.2.

### Configuration

The module generates `~/.config/llm-index/config.toml` (or
`/etc/llm-index/<owner>.toml`):

```toml
[[root]]
name = "documents"
path = "/home/alice/Documents"
tier = "private"          # default
kind = "auto"             # auto | local | network
interval = "15m"          # network roots only
# share = "nas:/export"   # optional; else recorded at first scan

[[root]]
name = "projects"
path = "/home/alice/Projects"
tier = "public"

[exclude]
paths = ["/home/alice/Documents/Credentials"]
lift_builtin = []          # only honoured for private roots

[limits]
max_file_mb = 50
memory_max_mb = 1024       # MemoryMax of the index service (all processes)
workers = 2                # minimum 2
backoff_max = "60m"
```

### Nix packaging

- `flake.nix` outputs: `packages.<system>.default` (`llm-index`, built with
  `rustPlatform.buildRustPackage`, model fetched with `fetchurl` by pinned
  revision and hash and installed under `share/llm-index/models/`),
  `homeManagerModules.default`, `nixosModules.default`, `checks.<system>.*`.
  Pure evaluation, no import-from-derivation.
- **Home Manager module** (primary), options under `services.llm-index`:
  `enable`, `package`, `stateDir`, `roots` (attrs: `path`, `tier`, `kind`,
  `interval`, `share`),
  `exclude`, `limits`, `registerPublic` (default `true`: adds
  `llm-index-public` to `programs.mcp.servers`, which current Home Manager's
  Claude Code and Codex modules can consume), and read-only outputs
  `mcpServers.public` / `mcpServers.private` (`{ command; args; }`) for wiring
  any client by hand. The private entry is never registered automatically: the
  user grants it by adding it to a specific client's configuration.
- **NixOS module**, `services.llm-index.instances.<owner>`: the same
  options except `registerPublic` (`programs.mcp` is a Home Manager option;
  NixOS users wire clients from `mcpServers.*`). Runs `index` as a system
  service as that owner (`User=<owner>`, not `DynamicUser`, which cannot read
  the owner's files or user-authenticated shares), with `StateDirectory`,
  `NoNewPrivileges`, `PrivateNetwork`, `RestrictAddressFamilies=AF_UNIX`,
  `SystemCallFilter=@system-service @sandbox` (`@sandbox` holds the
  `landlock_*` calls). `PrivateNetwork` is safe because kernel
  and FUSE mounts are served by other processes.
- **No mount-namespace options** (`ProtectSystem`, `ProtectHome`,
  `PrivateTmp`, `ReadWritePaths`) in either unit: setting them up remounts
  every submount, which blocks on a dead hard NFS mount before `llm-index`
  even starts, and in a user service they need unprivileged user namespaces.
  The Home Manager user service sets `NoNewPrivileges`, `SystemCallFilter`
  and `RestrictAddressFamilies`, none of which needs a namespace.
- **Read-only enforcement is Landlock, inside the process.** The
  coordinator, at start, applies a ruleset that handles **write** access
  only (and, ABI 4+, TCP): writes allowed beneath its state directory and
  `/proc` (so each worker can set its own `oom_score_adj`; an unprivileged
  process can write only its own entries there), nowhere else; reads stay unrestricted, so it can read config through store
  symlinks, `mountinfo`, and add inotify watches. Workers it spawns inherit
  that and add their own stricter, read-limiting ruleset (above); Landlock
  rulesets only stack tighter, which is the order needed. Without Landlock
  (kernel without the LSM) `index` refuses to start and names the reason;
  there is no override, because the intent requires read-only access. v0.1
  supports Home Manager on NixOS only (intent); the reference host's kernel
  runs `landlock` among its LSMs, and the plan's first step confirms the
  pinned nixpkgs default enables it.
- The package installs `share/llm-index/AGENTS.snippet.md`: when to use the
  index, the tools, and that passages are untrusted. The module exposes it as
  `services.llm-index.agentInstructions` for users to append to their agent
  rules.

## Alternatives rejected

| Alternative | Why not |
| --- | --- |
| `sqlite-vec` (`vec0` table or its scalar functions) | `vec0` KNN picks candidates inside the virtual table, so joined filters can apply after selection and lose eligible hits; it is brute force anyway. Its scalar functions need `vec_int8()` wrapping and add a native dependency for what is a 10-line int8 dot product. |
| `notify` crate (recursive watches) | Its recursive mode descends into mounts below a local root, which can reach a dead network mount from the coordinator. Per-directory watches on worker-listed directories keep that out. |
| systemd `ProtectSystem` / `ProtectHome` | Remounting submounts blocks on a dead hard NFS mount before the service starts; user services need user namespaces. Landlock gives the read-only guarantee without either. |
| Resolving root paths in `mcp` for authorization | `realpath` on a dead share blocks search; on an unmounted one it fails. Canonical roots make string matching exact. |
| `model2vec-rs` crate, or a memory map in `mcp` | Both make the 129 MB matrix resident (heap, or mapped pages that accumulate across diverse queries), breaking the 100 MB bound while warm; `model2vec-rs` also pulls `hf-hub` by default. The pooling it does is about 50 lines. |
| `RLIMIT_AS` as the memory cap | Limits virtual reservations, not RSS: allocators that reserve large ranges fail far below the real limit, and per-worker limits do not add up to the service cap. The cgroup cap plus `oom_score_adj` does. |
| Porter stemming in FTS5 | Makes keyword search stemmed, contradicting "exact words"; meaning search covers variants. |
| Relying on systemd sandboxing for read-only in the user service | Needs unprivileged user namespaces, which a host may disable; Landlock applies from inside the process. |
| Adopt ck (Rust, MIT/Apache, MCP) | Code-only, one `.ck/` index per directory, no documents, tiers or network handling. Its approach (tree-sitter, RRF, BLAKE3 cache) is reused as a pattern. |
| Adopt Semble or VectorCode | Python, code-only, no tiers. |
| Adopt qmd | Node, markdown-first, ~2 GB of models in its full setup. |
| Adopt haiku.rag | Python + Docling + LanceDB: closure far over 500 MB; not in nixpkgs. |
| Recoll or LocalSearch as the base | GPL (licence constraint), no vectors, no MCP. |
| Python small build | Larger closure, slower stdio cold start, nixpkgs Python churn. |
| Go | CGo for SQLite, tree-sitter and pdfium anyway; weaker extraction ecosystem. |
| `bge-small-en-v1.5` via ONNX as default | Adds ONNX Runtime and ~120 MB RSS while loaded, slower indexing on CPU. Better quality; candidate for an opt-in v0.2 profile. |
| Qwen3-Embedding-0.6B / EmbeddingGemma default | Too heavy for the laptop bounds; EmbeddingGemma is not permissively licensed. |
| One database with a `tier` column | Tier would become a query parameter; the intent forbids that boundary. |
| LanceDB / tantivy | A directory store needing compaction, or a second store without vectors; SQLite holds both in one file. |
| `git ls-files` for discovery | Executes repository configuration in untrusted repos. |
| inotify for network roots | Never sees remote changes. |
| HTTP listener in v0.1 | No authenticated listener is needed for stdio clients; Open WebUI's Streamable HTTP is v0.2 behind a token file. |
| Poppler `pdftotext` | GPL. |

## Risks

| Risk | Where | Mitigation |
| --- | --- | --- |
| Static embeddings rank worse than transformer models | all | Hybrid with BM25; evaluation set in checks; opt-in better model in v0.2 |
| pdfium build or closure larger than expected | build | Measure in the first plan step; fallback `pdf-extract` (pure Rust, weaker) |
| A stuck NFS worker in D-state survives `SIGKILL` | hosts with hard NFS mounts | Counted until reaped, one per share, out of the pool after 30 s, network jobs capped at `workers - 1` |
| Kernel without Landlock | non-default kernels | `index` refuses to start and says why; documented as a requirement |
| A user configures a root or exclusion through a symlink | all | Public tier closed until the path validates; `status` names it |
| A config change touching a dead share closes the public tier | NAS outage during reconfiguration | By design (no disclosure); `status` says why; reverting the change reopens it |
| Many dead shares at once | NAS outage | One stuck worker per share, `TasksMax` sized for all of them, healthy shares and local roots continue |
| Exact vector scan slows past ~1M chunks | large corpora | Filters shrink the scan; ANN (for example `vec0` partitions) is a later option |
| A share remounted from a different source at the same path | NAS changes | Identity check before and after every scan; mismatch never deletes |
| Tier leak through a bug | all | Process boundary, defence-in-depth filter, tier tests in VM checks |
| Prompt injection in indexed passages | clients | Untrusted wrapping, character stripping, read-only tools; clients still decide |
| Indexing many scanned PDFs on a laptop | v0.2 | OCR not in v0.1 |
| Home Manager `programs.mcp` integration differs per client | registration | Raw `mcpServers.*` outputs as the fallback |
| int8 quantisation loses too much ranking quality | search | The recall@5 check compares int8 against float32 on the fixture; fallback `float32` (2 KB per chunk, 600 MB scan at 300,000 chunks) |
| pdfium build in the pinned nixpkgs enables V8 or XFA | build | Plan step checks the derivation flags; override them off if needed |

## Verification

- `cargo test`: chunkers (declaration ranges for split functions), title
  extraction, format dispatch (`.docx`, `.xlsx`, PDF with NULs are indexed;
  a `.docx` that is not a ZIP is `mismatch`), tier routing, `visible()` for
  nested private roots, removed roots, changed root paths and exclusions,
  fail-closed on missing or invalid config, denylist anchoring and case
  (including a root inside `.ssh/`, and lifts honoured only for private
  roots, `.config/gcloud/` matched under `/home/<owner>`, `id_map.rs` not
  denied), canonical-root check, nested roots indexed once, symlink
  skipping, the `openat2` swap races (the root itself, or a directory beneath
  it, replaced by a symlink between listing and open is not read), zip-bomb
  guard, deletion
  only after complete scan, embed cache key changes with path, RRF ordering,
  and a filtered meaning search where every globally nearest chunk is
  ineligible.
- `nix flake check` runs:
  - **Fixture search test** (sandboxed derivation, no network, empty cache):
    fixture tree with Markdown, HTML, PDF, `.docx`, `.odt`, `.xlsx`, `.ods`,
    `.csv`, a git repo with `.gitignore`, a symlink to a denied file, a
    `.env`, `.netrc`, a zip bomb, a long-line HTML page. A labelled set of 40
    queries over MCP stdio covers meaning, exact words, title, path, folder,
    type and date; the check fails if hybrid recall@5 is below 0.8. It also
    checks: `.env`, `.netrc`, the symlink target and the bomb are not indexed;
    the long-line HTML is; a code hit's `lines` plus `get` return the whole
    function.
  - **Tier test:** the public server returns nothing from private roots in
    `search`, `get`, `recent` or `status` (no paths, titles, names or
    counts).
  - **Reclassification test:** with the indexer stopped, (a) move a root from
    public to private, (b) add a private child root under a public root, (c)
    add an exclusion, (d) remove a root, (e) corrupt `config.toml`; after each,
    every public tool returns nothing from the affected paths (an error for
    (e)), including with the share of (a)–(c) unmounted and with it hung.
    (f) Add an exclusion and (g) a private child root, each written through a
    symlink: the public tier closes (`pending validation`) and never returns
    the aliased files. (h) After (b) with the share dead, public stays closed
    until the share returns; removing a root or making it private applies
    at once even then. Search ranking: a unit test with known vectors checks
    that the most similar chunk ranks first.
  - **Sandbox test** (VM): under the running service, a worker extracts
    files and reads `mountinfo` (works), and tries to create a file in a root
    and to open a TCP connection (both fail); the coordinator cannot write
    outside its state directory or `/proc`; a worker's `oom_score_adj` reads
    1000. Booted without Landlock, `index` refuses to
    start.
  - **Network VM test** (`nixosTest`, two nodes, short backoff): NFS server
    and client; two roots on one share (subdirectories) plus a healthy local
    root. Start the client service once **with the server already down**
    (both roots get one probe between them, the local root indexes), then
    bring the server up and index all. Stop the server across three backoff
    cycles while
    editing the local root: search answers, NFS entries are `stale`, nothing
    is deleted, `status` shows `offline`, at most one worker process exists
    for the share at every sample, and the local edit is indexed. Unmount the
    share and mount a different export at the same path: `offline (identity
    mismatch)`, nothing deleted. Restore: a deleted file disappears only after
    the next complete scan, and a remote edit is found within `interval` + 60
    seconds. An `x-systemd.automount` share indexes like a plain mount, and
    a share mounted after startup is scanned without waiting for the daily
    pass. Mounting an empty filesystem over a subdirectory of an indexed
    share is a mismatch and deletes nothing. With two dead shares and one
    healthy share, the healthy one keeps being scanned.
  - **Watch degradation test** (VM): with `fs.inotify.max_user_watches` set
    below the root's directory count, and separately with
    `max_queued_events` forced to overflow, the root shows `degraded` and a
    batch of 100 edits is searchable within 5 minutes.
  - **Access test** (VM): another user cannot read the state directory or the
    databases, and has no socket or port to query. A state directory inside a
    root or below a `.stfolder` makes `index` refuse to start.
  - **Freshness in session:** with one `mcp` session open and config
    unchanged, a file added or replaced by the indexer appears in that
    session's next search.
  - **Module eval tests:** Home Manager and NixOS modules evaluate with
    minimal config; the private server is not in `programs.mcp.servers`.
  - **Closure check:** `nix path-info -S` of the default package is 500 MB or
    less.
- **Benchmark** on the reference laptop (x86_64, 4 cores, 8 GB, no GPU),
  scripted in `bench/` and recorded with results in `docs/benchmark.md`:
  - Corpus: built by a pinned generator from fixed-hash public sources, 10,000
    files: 40% code, 20% Markdown/text, 10% HTML, 15% PDF (text layer, mean 10
    pages), 10% `.docx`/`.odt`, 5% spreadsheets/CSV; its total bytes, pages
    and BLAKE3 manifest are recorded.
  - Initial index in 2 hours or less, with `status` progress increasing.
  - Indexing memory: the service cgroup's `memory.peak` (coordinator plus
    workers) 1 GB or less.
  - `mcp` RSS 100 MB or less when idle, and again after 1,000 distinct
    queries drawn from the corpus vocabulary (warm).
  - A batch of 100 local edits searchable within 5 minutes.
