# Spec: nixarchy-llm-index v0.1

Scope is v0.1 from the approved intent. v0.2 items appear only where v0.1
must leave room for them.

## Design

### Shape

One Rust binary, `llm-index`, with four subcommands, plus Nix modules that
run and register it.

```text
                        config.toml (generated by the module)
                                   │
  ┌────────────── llm-index index (one per owner, systemd service) ──────────┐
  │ coordinator: roots, schedule, queue, tier routing, purge                │
  │   ├─ local watcher (inotify via `notify`)                               │
  │   ├─ poll scheduler for network roots                                   │
  │   └─ worker pool: `llm-index worker` child processes (scan + extract)   │
  │ writes: public.db, private.db  (SQLite: FTS5 + sqlite-vec)              │
  └─────────────────────────────────────────────────────────────────────────┘
        ▲ reads only                                   ▲ reads only
  llm-index mcp --tier public                   llm-index mcp --tier private
  (stdio, spawned by a cloud client)            (stdio, spawned by a granted
   opens public.db only                          local-only client; opens both)

  llm-index status   — roots, freshness, offline shares, sizes
```

| Subcommand | Runs as | Purpose |
| --- | --- | --- |
| `index` | long-running service | the only writer; schedules work, owns the databases |
| `worker` | child of `index`, short-lived | lists one root or extracts one file; may block or crash without harm |
| `mcp` | spawned per client session over stdio | read-only search and read tools |
| `status` | CLI | human and script view of index health |

### Why Rust

Both research rounds (Claude, Codex, agy) agreed: a single native binary
meets the closure and memory bounds; the crates needed exist and are
permissively licensed; Python needs a larger closure and slower cold start for
a stdio server spawned per session; Go needs CGo for SQLite, tree-sitter and
PDF anyway.

No GPU, ML framework, ONNX runtime, Ollama, database server or network
service. pdfium is the only large native library; it is BSD-licensed, in
nixpkgs and used by both research candidates.

### Storage and tiers

- State lives in `$XDG_STATE_HOME/llm-index/` (user service) or
  `/var/lib/llm-index/<owner>/` (system service), mode `0700`, files `0600`.
  The module refuses a state directory on a network or FUSE filesystem
  (checked with `statfs` at start).
- **Two databases**: `public.db` and `private.db`, same schema. A document
  lives in exactly one. Tier separation is a process boundary: `mcp --tier
  public` opens only `public.db` and has no flag, path or tool that reaches
  `private.db`. `mcp --tier private` opens both and merges results.
- Schema (per database): `roots(name, resolved_path, kind, share_id,
  state)`, `files(root_id, relpath, abspath, title, type, size, mtime_ns,
  blake3, state)`, `chunks(file_id, ord, kind, start, end, decl_start,
  decl_end, heading_or_symbol, text, vec)`, `chunks_fts` (FTS5 over chunk
  text), `files_fts` (FTS5 over title and path), `embed_cache(input_blake3,
  vector)`, `meta(model_rev, schema_version)`. Both FTS tables use the
  `unicode61` tokenizer with diacritics folded and **no stemming**.
- File identity is `(root_id, relpath)`; `root_id` is the configured root
  name, never device or inode numbers. `abspath` is the resolved root path
  plus `relpath`, kept so authorization can re-derive the current root (see
  Authorization). Content identity is BLAKE3.
- The embed cache key is BLAKE3 of the full embedding input (path and symbol
  prefix plus text) and the model revision. A moved file is re-embedded; an
  unchanged file is not.
- Vectors are scalar-quantised to `int8` and stored as a plain BLOB column of
  `chunks` (512 bytes per chunk, about 50 MB per 100,000 chunks). No `vec0`
  virtual table: see Search.
- **Titles** are extracted per file: Markdown front-matter `title` or first
  H1; HTML `<title>`; PDF `Title` metadata, else the first text line; `.docx`
  / `.odt` `dc:title`, else the first heading; spreadsheets and code: the
  filename.

### Search

`search(query, mode?, field?, folder?, type?, after?, before?, limit?)`:

- `mode`: `hybrid` (default), `words` or `meaning`.
- `field`: `any` (default), `title` or `path`. `title` and `path` search
  `files_fts` only and return one hit per file.
- **Words** means whole tokens, case- and diacritic-insensitive, no stemming;
  `"quoted text"` is a phrase. Morphological variants are the meaning
  search's job.

1. Eligible files: the SQL filters (`folder` as a path prefix, `type`,
   `after` / `before` on file mtime) joined with the authorization set (see
   below). Both apply before any ranking, for both legs.
2. Words: FTS5 BM25 over `chunks_fts` and `files_fts`, eligible files only.
3. Meaning: embed the query; exact distance with `sqlite-vec`'s scalar
   `vec_distance_cosine` over the `vec` column of eligible chunks, `ORDER BY`
   distance `LIMIT`. This is an exact scan, so a selective filter never loses
   the nearest eligible chunk. At 300,000 chunks the scan reads about 150 MB
   from page cache.
4. Fuse with reciprocal rank fusion (k = 60).
5. Each hit returns `path`, `title`, `mtime`, `type`, `tier` (private server
   only), `stale`, `lines` (code: the whole declaration, `decl_start`–
   `decl_end`) or `page`, `symbol` or `heading`, and a preview passage of at
   most 800 characters. The full text comes from `get`.

Other tools: `get(path, start?, end?)` reads indexed text of one document in
line or page ranges (for code the indexed text is the original source, so a
hit's `lines` returns the whole function); `recent(days, folder?, type?)`
lists changed files; `status()` shows roots and freshness. All tools are
read-only (`readOnlyHint`). Every passage is wrapped as untrusted document
content with its path, and Unicode tag, bidi-override and zero-width
characters are stripped at ingest.

**Model memory.** The embedding matrix is memory-mapped read-only from the
store, never copied to the heap. A query touches only the rows of its own
tokens (a few KB), so `mcp` RSS stays at SQLite caches, the tokenizer (about
5 MB) and those pages, whether idle, warm or busy. No load/unload timer.

### Authorization (both servers, every tool)

One function, `visible(abspath) -> tier | none`, decides every row any tool
returns: `search`, `get`, `recent` and `status` alike.

- It recomputes from the **current** `config.toml`: the longest configured
  root whose resolved path contains `abspath` gives the tier; no matching
  root gives `none`; a match on a user exclusion or the built-in denylist
  (with lifts only for private roots) gives `none`. The stored `root_id` and
  database are never trusted on their own, so a private child root added
  under a public root, a removed root or a changed root path all take effect
  without the indexer.
- The public server returns a row only when `visible` is `public`. `status`
  on the public server lists only public roots; private root names, paths and
  counts never appear.
- The server re-reads `config.toml` when its mtime or inode changes and then
  rebuilds a temporary table of visible file ids, which every query joins.
  Missing, unreadable or invalid config makes every tool return an error:
  fail closed, never fall back to the last good config.
- The indexer purges the same rows at its next pass. Until then the filter
  alone hides them, mounted share or not.

### Indexing

- **Discovery** uses the `ignore` walker: `.gitignore`, `.git/info/exclude`,
  global gitignore, plus `.llmindexignore`, the built-in denylist and user
  excludes. Git is never executed: running `git` inside an untrusted
  repository can execute its configuration (`core.fsmonitor`, hooks), which
  the threat model forbids.
- **Format dispatch first.** The extractor is chosen by extension and
  confirmed by magic bytes (`%PDF-`; ZIP with the expected
  `[Content_Types].xml` or `mimetype` member). Office and PDF files never go
  through the text heuristics below. A file whose magic does not match its
  extension is skipped as `mismatch`.
- **Skipped by default:** `.git/`, `node_modules/`, `target/`, `.direnv/`,
  `result*`, directories with `CACHEDIR.TAG`, lockfiles, files over 50 MB.
  For plain-text and code files only: binary (NUL in the first 8 KB or not
  valid UTF-8), minified (`.js`, `.css`, `.json`, `.map` with average line
  length over 250), and `@generated` in the first 4 KB. HTML and documents
  are never dropped as minified.
- **Built-in denylist** (all tiers; liftable for private roots only):
  `.env*`, `*.pem`, `*.key`, `id_*`, `*.p12`, `*.pfx`, `*.kdbx`, `*.age`,
  `.netrc`, `.git-credentials`, `.npmrc`, `.pypirc`, `.docker/config.json`,
  `.cargo/credentials*`, `.ssh/`, `.gnupg/`, `.password-store/`, `.aws/`,
  `.azure/`, `.kube/`, `.config/gcloud/`, `.config/gh/`, `.config/sops/`,
  `.local/share/keyrings/`, `.claude/`, `.codex/`, `.gemini/`,
  `.antigravity/`, `.config/Antigravity/`, `.mozilla/`, `.thunderbird/`,
  `.config/google-chrome/`, `.config/chromium/`,
  `.config/BraveSoftware/`, `.config/vivaldi/`, `/run/agenix*`,
  `/run/secrets*`.
  Matching: gitignore syntax, case-insensitive, against the **absolute
  resolved path**, so a root that starts inside a denied directory is denied
  whole. Patterns without a leading `/` match at any depth; a trailing `/`
  denies the directory and everything under it. `lift_builtin` entries apply
  only while the file's current root is private.
- **Symlinks** are never followed. The walker runs with `follow_links(false)`
  and `same_file_system(true)`; a symlink is skipped and counted in `status`.
  Mounts inside a root are not crossed; mount them as their own root.
- **Open-time containment.** A configured root is resolved once (in a
  worker) and opened as a directory fd; tier and exclusion checks use the
  resolved path. Every file is opened with `openat2(root_fd, relpath,
  RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS |
  RESOLVE_NO_XDEV)` and `O_RDONLY | O_NOFOLLOW`, then `fstat` must show a
  regular file. A file or intermediate directory swapped for a symlink
  between listing and reading fails the open; nothing outside the root is
  read under the root's tier. Exclusion checks run on `relpath` before the
  open, and the denylist on the resolved absolute path.
- **Chunking:** code by tree-sitter declarations, packing small siblings up to
  about 512 tokens; a declaration larger than that is split, and every part
  records the declaration's full line range (`decl_start`, `decl_end`). The
  stored text is the original source; the path and enclosing symbol are a
  prefix of the embedding input only. Markdown by headings; other text by
  `text-splitter`; PDF by page; spreadsheets by sheet and row block.
- **Tier routing:** the longest matching root wins; a root's tier is
  `public` or `private` (default `private`). Moving a file across tiers
  deletes it from one database and inserts it into the other in one
  coordinator transaction per database, public delete first.

### Workers and network roots

- The coordinator never touches a configured root itself. Every `readdir`,
  `statx` and file read happens in a `worker` child process, talking JSON lines
  over a pipe.
- Each worker, before taking a job, applies a **Landlock** ruleset: read-only
  access to its one root and the read-only store, no write access anywhere,
  and (Landlock ABI 4+) no TCP bind or connect. It sets `oom_score_adj` to
  1000 and `RLIMIT_AS` to 4 GB (a runaway guard on virtual memory only; the
  real memory cap is the service cgroup, see Resource controls). Workers have
  a per-job timeout (scan: 10 minutes, extract: 30 seconds) and a
  decompression guard (zip members: total uncompressed size at most 100 times
  the archive and at most 500 MB). A worker that exceeds a limit or is
  OOM-killed marks its file `failed` with the reason; the file is retried only
  when its size or mtime changes.
- **Share identity.** A *share* is the backing source of the mount that
  contains a root: `(fstype, source, mount root)` from `/proc/self/mountinfo`,
  for example `nfs4 nas:/export /`. Several roots on one share (for example
  two subdirectories of it) share one identity. A root's expected identity is
  recorded at its first successful scan, or set with `share = "nas:/export"`.
  Root kind (`local` or `network`) follows from the fstype (NFS, CIFS/SMB2,
  FUSE incl. `fuse.sshfs`, `fuse.rclone`), overridable per root. All of this,
  including `statfs` and the root `realpath`, runs inside a worker, so a dead
  mount at startup blocks only that worker.
- **Local roots:** inotify events, debounced 2 seconds, plus a full
  reconciliation pass daily. If a watch cannot be added (`ENOSPC`, watch
  limit), the queue overflows (`IN_Q_OVERFLOW`) or the watcher fails, the
  root switches to `degraded`: an immediate reconciliation scan, then polling
  every 2 minutes until watching succeeds again. `status` shows the reason.
- **Network roots:** polled every `interval` (default 15 minutes) by a scan
  worker that lists `(relpath, size, mtime_ns)` using `statx` with
  `AT_NO_AUTOMOUNT` and the default sync mode (no `AT_STATX_DONT_SYNC`), so
  attributes are at most one attribute-cache period old, well inside the
  interval. Changed entries are queued for extraction on that share.
- **Mount check.** Before a scan, and again after it completes, the worker
  compares the containing mount's identity, and the root fd's `st_dev`, with
  the expected identity. Unmounted (the containing mount is now the parent
  filesystem), a different share mounted at the same place, or a change
  during the scan: the root is `offline (identity mismatch)` and the scan
  result is discarded.
- **One live worker per share.** At most one worker process (scan or
  extract) exists per share at any time, counting a worker until `waitpid`
  has reaped it, not until it was signalled. A worker that reports no
  progress for 30 seconds (progress = entries listed or bytes read, sent by
  the thread doing the I/O, never a timer thread) is sent `SIGKILL` and
  *abandoned*: the share is `offline`, and nothing new starts on it until
  that process has exited **and** backoff (doubling from 1 to 60 minutes) has
  expired. A worker stuck in uninterruptible sleep therefore blocks only its
  own share, forever if need be, and there is never a second one.
- **Pool capacity.** The pool (default 2) counts only live, non-abandoned
  workers, and network jobs may hold at most `workers - 1` slots, so local
  roots always keep one. An abandoned worker leaves the pool within 30
  seconds. Abandoned workers are bounded by the number of shares; `TasksMax`
  is a backstop.
- **Deletion only after a complete scan.** A file disappears from the index
  only when a scan of its root finished, passed both mount checks, and did
  not list it. Partial, failed, offline or mismatched scans never delete.
  Entries of an offline root are served with `stale: true`.

### Resource controls

The module sets on the `index` service: `Nice=19`,
`IOSchedulingClass=idle`, `CPUWeight=20`, `MemoryHigh=768M`, `MemoryMax=1G`
(option), `OOMPolicy=continue`, `TasksMax=64`, and a worker pool of 2
(option). `MemoryMax` caps the coordinator and all workers together. Workers
have `oom_score_adj=1000` and the coordinator keeps 0, so when the cgroup
hits its cap the kernel kills a worker, and `OOMPolicy=continue` keeps
systemd from stopping the service; the coordinator marks that file `failed`.
`mcp` is spawned by the client and inherits its limits. Battery pause is
v0.2.

### Configuration

The module generates `~/.config/llm-index/config.toml` (or
`/etc/llm-index/<owner>.toml`):

```toml
[[root]]
name = "documents"
path = "/home/alice/Documents"
tier = "private"          # default
kind = "auto"             # auto | local | network
interval = "15m"          # network roots only
# share = "nas:/export"   # optional; else recorded at first scan

[[root]]
name = "projects"
path = "/home/alice/Projects"
tier = "public"

[exclude]
paths = ["/home/alice/Documents/Credentials"]
lift_builtin = []          # only honoured for private roots

[limits]
max_file_mb = 50
worker_memory_mb = 1024
workers = 2
backoff_max = "60m"
```

### Nix packaging

- `flake.nix` outputs: `packages.<system>.default` (`llm-index`, built with
  `rustPlatform.buildRustPackage`, model fetched with `fetchurl` by pinned
  revision and hash and installed under `share/llm-index/models/`),
  `homeManagerModules.default`, `nixosModules.default`, `checks.<system>.*`.
  Pure evaluation, no import-from-derivation.
- **Home Manager module** (primary), options under `services.llm-index`:
  `enable`, `package`, `roots` (attrs: `path`, `tier`, `kind`, `interval`),
  `exclude`, `limits`, `registerPublic` (default `true`: adds
  `llm-index-public` to `programs.mcp.servers`, which current Home Manager's
  Claude Code and Codex modules can consume), and read-only outputs
  `mcpServers.public` / `mcpServers.private` (`{ command; args; }`) for wiring
  any client by hand. The private entry is never registered automatically: the
  user grants it by adding it to a specific client's configuration.
- **NixOS module**, `services.llm-index.instances.<owner>`: same options,
  runs `index` as a system service as that owner (`User=<owner>`, not
  `DynamicUser`, which cannot read the owner's files or user-authenticated
  shares), with `ProtectSystem=strict`, `ProtectHome=read-only`,
  `ReadWritePaths` = state directory, `NoNewPrivileges`, `PrivateNetwork`,
  `PrivateTmp`, `RestrictAddressFamilies=AF_UNIX`, `SystemCallFilter`
  `@system-service`. `PrivateNetwork` is safe because kernel and FUSE mounts
  are served by other processes.
- **Read-only enforcement does not depend on the unit.** systemd's
  filesystem namespacing in a *user* service needs unprivileged user
  namespaces, which a host may disable. So the guarantee comes from Landlock
  in every worker (above), and the coordinator applies its own Landlock
  ruleset at start: write access only to its state directory, read access to
  the store, config and `/proc`; the coordinator never opens a root. Without
  Landlock (kernel without the LSM, or `security.lsm` without it) `index`
  refuses to start, naming the reason; `limits.allow_unsandboxed = true`
  overrides that, and `status` then shows `unsandboxed`. The Home Manager
  user service also sets the systemd options above; they are extra, not
  relied on. v0.1 supports Home Manager on NixOS only (intent); the
  reference host's kernel runs `landlock` among its LSMs, and the plan's
  first step confirms the pinned nixpkgs default enables it.
- The package installs `share/llm-index/AGENTS.snippet.md`: when to use the
  index, the tools, and that passages are untrusted. The module exposes it as
  `services.llm-index.agentInstructions` for users to append to their agent
  rules.

## Alternatives rejected

| Alternative | Why not |
| --- | --- |
| `vec0` virtual table for vectors | Its KNN picks candidates inside the virtual table, so joined folder, type and date filters can apply after candidate selection and lose eligible hits. `vec0` is brute force anyway; an exact scan over a plain column is as fast and correct under any filter. |
| `model2vec-rs` crate | Loads the whole 129 MB matrix onto the heap, breaking the 100 MB idle bound while warm, and pulls `hf-hub` by default. The pooling it does is about 50 lines. |
| `RLIMIT_AS` as the memory cap | Limits virtual reservations, not RSS: allocators that reserve large ranges fail far below the real limit, and per-worker limits do not add up to the service cap. The cgroup cap plus `oom_score_adj` does. |
| Porter stemming in FTS5 | Makes keyword search stemmed, contradicting "exact words"; meaning search covers variants. |
| Relying on systemd sandboxing for read-only in the user service | Needs unprivileged user namespaces, which a host may disable; Landlock applies from inside the process. |
| Adopt ck (Rust, MIT/Apache, MCP) | Code-only, one `.ck/` index per directory, no documents, tiers or network handling. Its approach (tree-sitter, RRF, BLAKE3 cache) is reused as a pattern. |
| Adopt Semble or VectorCode | Python, code-only, no tiers. |
| Adopt qmd | Node, markdown-first, ~2 GB of models in its full setup. |
| Adopt haiku.rag | Python + Docling + LanceDB: closure far over 500 MB; not in nixpkgs. |
| Recoll or LocalSearch as the base | GPL (licence constraint), no vectors, no MCP. |
| Python small build | Larger closure, slower stdio cold start, nixpkgs Python churn. |
| Go | CGo for SQLite, tree-sitter and pdfium anyway; weaker extraction ecosystem. |
| `bge-small-en-v1.5` via ONNX as default | Adds ONNX Runtime and ~120 MB RSS while loaded, slower indexing on CPU. Better quality; candidate for an opt-in v0.2 profile. |
| Qwen3-Embedding-0.6B / EmbeddingGemma default | Too heavy for the laptop bounds; EmbeddingGemma is not permissively licensed. |
| One database with a `tier` column | Tier would become a query parameter; the intent forbids that boundary. |
| LanceDB / tantivy | A directory store needing compaction, or a second store without vectors; SQLite holds both in one file. |
| `git ls-files` for discovery | Executes repository configuration in untrusted repos. |
| inotify for network roots | Never sees remote changes. |
| HTTP listener in v0.1 | No authenticated listener is needed for stdio clients; Open WebUI's Streamable HTTP is v0.2 behind a token file. |
| Poppler `pdftotext` | GPL. |

## Risks

| Risk | Where | Mitigation |
| --- | --- | --- |
| Static embeddings rank worse than transformer models | all | Hybrid with BM25; evaluation set in checks; opt-in better model in v0.2 |
| pdfium build or closure larger than expected | build | Measure in the first plan step; fallback `pdf-extract` (pure Rust, weaker) |
| A stuck NFS worker in D-state survives `SIGKILL` | hosts with hard NFS mounts | Counted until reaped, one per share, out of the pool after 30 s, network jobs capped at `workers - 1` |
| Kernel without Landlock | non-default kernels | `index` refuses to start unless `allow_unsandboxed`; `status` shows it |
| Exact vector scan slows past ~1M chunks | large corpora | Filters shrink the scan; ANN (for example `vec0` partitions) is a later option |
| A share remounted from a different source at the same path | NAS changes | Identity check before and after every scan; mismatch never deletes |
| Tier leak through a bug | all | Process boundary, defence-in-depth filter, tier tests in VM checks |
| Prompt injection in indexed passages | clients | Untrusted wrapping, character stripping, read-only tools; clients still decide |
| Indexing many scanned PDFs on a laptop | v0.2 | OCR not in v0.1 |
| Home Manager `programs.mcp` integration differs per client | registration | Raw `mcpServers.*` outputs as the fallback |
| `vec_distance_cosine` on `int8` BLOBs not supported by the pinned `sqlite-vec` | build | Checked in the first plan step; fallback is `float32` (2 KB per chunk) |
| pdfium build in the pinned nixpkgs enables V8 or XFA | build | Plan step checks the derivation flags; override them off if needed |

## Verification

- `cargo test`: chunkers (declaration ranges for split functions), title
  extraction, format dispatch (`.docx`, `.xlsx`, PDF with NULs are indexed;
  a `.docx` that is not a ZIP is `mismatch`), tier routing, `visible()` for
  nested private roots, removed roots, changed root paths and exclusions,
  fail-closed on missing or invalid config, denylist anchoring and case
  (including a root inside `.ssh/`, and lifts honoured only for private
  roots), symlink skipping, the `openat2` swap race (a directory replaced by a
  symlink between listing and open is not read), zip-bomb guard, deletion
  only after complete scan, embed cache key changes with path, RRF ordering,
  and a filtered meaning search where every globally nearest chunk is
  ineligible.
- `nix flake check` runs:
  - **Fixture search test** (sandboxed derivation, no network, empty cache):
    fixture tree with Markdown, HTML, PDF, `.docx`, `.odt`, `.xlsx`, `.ods`,
    `.csv`, a git repo with `.gitignore`, a symlink to a denied file, a
    `.env`, `.netrc`, a zip bomb, a long-line HTML page. A labelled set of 40
    queries over MCP stdio covers meaning, exact words, title, path, folder,
    type and date; the check fails if hybrid recall@5 is below 0.8. It also
    checks: `.env`, `.netrc`, the symlink target and the bomb are not indexed;
    the long-line HTML is; a code hit's `lines` plus `get` return the whole
    function.
  - **Tier test:** the public server returns nothing from private roots in
    `search`, `get`, `recent` or `status` (no paths, titles, names or
    counts).
  - **Reclassification test:** with the indexer stopped, (a) move a root from
    public to private, (b) add a private child root under a public root, (c)
    add an exclusion, (d) remove a root, (e) corrupt `config.toml`; after each,
    every public tool returns nothing from the affected paths (an error for
    (e)).
  - **Sandbox test** (VM): a worker started by the running service tries to
    create a file in a root and to open a TCP connection; both fail. The same
    run with Landlock disabled in the kernel makes `index` refuse to start.
  - **Network VM test** (`nixosTest`, two nodes, short backoff): NFS server
    and client; two roots on one share (subdirectories) plus a healthy local
    root; index all. Stop the server across three backoff cycles while
    editing the local root: search answers, NFS entries are `stale`, nothing
    is deleted, `status` shows `offline`, at most one worker process exists
    for the share at every sample, and the local edit is indexed. Unmount the
    share and mount a different export at the same path: `offline (identity
    mismatch)`, nothing deleted. Restore: a deleted file disappears only after
    the next complete scan.
  - **Watch degradation test** (VM): with `fs.inotify.max_user_watches` set
    below the root's directory count, and separately with
    `max_queued_events` forced to overflow, the root shows `degraded` and a
    batch of 100 edits is searchable within 5 minutes.
  - **Access test** (VM): another user cannot read the state directory or the
    databases, and has no socket or port to query.
  - **Module eval tests:** Home Manager and NixOS modules evaluate with
    minimal config; the private server is not in `programs.mcp.servers`.
  - **Closure check:** `nix path-info -S` of the default package is 500 MB or
    less.
- **Benchmark** on the reference laptop (x86_64, 4 cores, 8 GB, no GPU),
  scripted in `bench/` and recorded with results in `docs/benchmark.md`:
  - Corpus: built by a pinned generator from fixed-hash public sources, 10,000
    files: 40% code, 20% Markdown/text, 10% HTML, 15% PDF (text layer, mean 10
    pages), 10% `.docx`/`.odt`, 5% spreadsheets/CSV; its total bytes, pages
    and BLAKE3 manifest are recorded.
  - Initial index in 2 hours or less, with `status` progress increasing.
  - Indexing memory: the service cgroup's `memory.peak` (coordinator plus
    workers) 1 GB or less.
  - `mcp` RSS 100 MB or less when idle, and again after 100 queries (warm).
  - A batch of 100 local edits searchable within 5 minutes.
