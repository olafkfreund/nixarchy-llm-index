# Intent: an Omarchy shell plugin for llm-index status and settings

## Problem

llm-index runs as a background user service on p620 and razer with no desktop
interface. Status comes only from `llm-index status` in a terminal, or from the
MCP `status` tool an agent calls. The effective configuration is a read-only
`config.toml` generated by Home Manager. So nothing on the desktop shows that:

- the service has stopped or failed;
- a root is `offline`, `degraded` or has a configuration error, while the
  service itself keeps running. On p620, `source` was offline with
  `identity mismatch` from 2026-11-14 (#14), and nobody noticed until a manual
  `llm-index status`;
- a first index (or another large backlog) is still running, and how far it
  has got;
- which settings are in effect (roots, tiers, intervals, limits, exclusions).

Today's `status` takes about 3 s per call on p620 (1.4 GB public database,
measured 2026-11-15), almost all of it in full-table file and chunk counts. A
surface that called it on a timer would load the machine.

## Proposed outcome

An Omarchy shell plugin for the owner at the desktop:

- **Attention indicator in the bar.** It appears when something needs the
  owner: the service is stopped or failed, a root is not `ok`, or a first
  index or large backlog is running. Routine incremental indexing of a few
  edited files does not show it. When nothing needs attention it takes no
  space.
- **Panel** opened from the indicator, and still reachable from the shell
  when the indicator is hidden. It is keyboard-driven like the shell's other
  panels and shows:
  - **Status:** the service state, each root with its tier, state, reason,
    last scan, queued/done and file and chunk counts, configuration errors,
    and database sizes;
  - **Settings:** a read-only summary of the effective config (roots by name,
    tier and kind, intervals, limits, the number of exclusions), with a
    "managed by Nix" hint naming where to change it.
- **Actions:** Refresh, Restart service (confirmed; the unit already runs the
  sandbox self-test before every start), and Open log in a terminal.
- **Stale or unavailable data is never shown as healthy.** If the status
  cannot be read, or the service is stopped while the databases still say
  `ok`, the panel says so.
- Installed on p620 and razer through nixos_config.

## Affected users and systems

- This repository: the CLI's status output, a new plugin, the flake outputs
  and checks, and the docs.
- nixos_config: the shared llm-index host module and the flake input. Hosts:
  p620 and razer.
- Possibly nixarchy, depending on open questions 1 and 2.
- The owner, at the desktop. Agents are not users of the plugin.

## Constraints

- **Settings stay declarative.** The plugin never writes `config.toml`, a
  runtime override, or nixos_config. Changing roots, tiers or exclusions stays
  a reviewed Nix change.
- **Private-tier metadata stays inside the open panel.** Everything about a
  private root (its name, existence, state, reason, counts, its configuration
  errors, and `private.db`'s size) appears only in the open panel. Never in
  the bar tooltip, shell IPC replies, the shell's own logs, or notifications.
  The public MCP `status` already hides the same things
  (`docs/security.md`).
- **No indexed content.** The plugin shows no file paths, titles or text from
  the index, and never calls `search`, `get` or `recent`. Diagnostic text
  (reasons, configuration errors) must be path-free or redacted, since
  rendering as plain text does not remove a path.
- **Untrusted text is inert.** Every string from the index, the config or the
  service renders as plain text. It is never markup, so it can't load a
  resource or a link.
- **Cheap when idle.** With the panel closed, the background check costs
  milliseconds and never runs the full-table counts. The full status runs
  only when the owner opens the panel or asks to refresh. Measured on p620
  and razer.
- **No new daemon surface.** No control socket and no pause or reindex in this
  task. Stopping the service is not presented as "pause".
- **Omarchy conventions.** Theme, keyboard handling and panel behaviour match
  the shell's own plugins. Nothing outside the shell writes `shell.json`
  (that breaks bar IPC, per `nixarchy/docs/internals/shell-json-reload.md`).
  A later disable by the owner stays disabled.
- **The text `llm-index status` output stays as it is.**
- The usual rules: agents don't commit or deploy. p510 is out of scope.
- **Security model unchanged.** This doesn't change the model: any process
  running as the owner can already read both databases
  (`docs/security.md`). The rules above keep the plugin from adding new
  places private metadata shows, such as the bar, IPC, logs or screenshots of
  the closed bar.

## Open questions

1. **How it gets turned on.** `programs.nixarchy.plugins` installs a plugin
   but does not enable it (`nixarchy/modules/home.nix:708`). The options:
   - enable it once by hand with `omarchy plugin enable <id>` (no nixarchy
     change), or
   - make it a nixarchy default plugin that is "on wherever llm-index is",
     like podman and devenv (a nixarchy change).

   Draft assumes: enable it once by hand.
2. **The way in when the indicator is hidden.** A shell menu row may need a
   nixarchy or nixos_config menu change. A keybinding needs only nixos_config.
   Draft assumes: a keybinding, plus a menu row if the spec finds a
   plugin-only way.
3. **Private roots and the indicator.** May a failing or indexing private
   root wake the indicator, with a generic tooltip that names no root? Draft
   assumes: yes. Otherwise a broken `docs` root goes unnoticed, which is the
   problem this task exists to fix.
4. **Configuration error paths in the panel.** These are configured root or
   exclusion paths, not indexed content. Show them in the open panel, or
   redact them? Draft assumes: redact to the root name.
5. **Plugin ID.** `olafkfreund.llm-index` (your own plugins' namespace, such
   as `olafkfreund.gmessages`) or `nixarchy.llm-index` (the first-party
   namespace, fitting if question 1 goes the default-plugin way)? Draft
   assumes: `olafkfreund.llm-index`.
6. **Order against #14.** #14 (a root goes offline after a machine restart,
   because its identity uses `/dev/sdX`) breaks p620's code search today.
   Draft assumes: fix #14 first as its own task, then this plugin shows that
   kind of failure.
