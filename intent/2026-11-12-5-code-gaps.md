# Intent: close three code gaps found while documenting v0.1

Approved by the owner as stated in issue #5 ("do #5 approved", 2026-11-12).
Revised during spec review: config and module validation added to scope
(see Affected), so it needs approval again.

## Problem

Writing the v0.1 docs (#4) showed three places where the code protects less
than intended:

1. **File paths reach agents unsanitized.** `search` and `recent` return
   `path` as stored, and `get` echoes it. Titles, headings, symbols, sheet
   names and passages have control, bidi and tag characters stripped
   (`src/sanitize.rs`), but paths do not. A file named with a right-to-left
   override or invisible tag characters can show an agent (and a human
   reading the transcript) a misleading name, or carry hidden instructions.
2. **`limits.maxCells` covers XLSX only.** ODS and XLS sheets are loaded
   whole with no cell budget (`src/extract/sheet.rs`); only the fixed
   20 MiB input cap applies. A small, sparse or highly compressed workbook
   can still describe a huge range.
3. **Unknown MCP argument names are ignored.** The argument structs in
   `src/mcp.rs` accept unknown fields, so a typo such as `foler` silently
   drops the filter and returns broader results than the agent asked for.

## Proposed outcome

- No MCP response contains a path with characters `sanitize` would strip,
  and `get` still works for every path a tool returned.
- ODS and XLS workbooks over `maxCells` fail as `too large`, as XLSX does.
- An MCP call with an unknown argument name fails with an error naming the
  argument, on all four tools (`status` accepts no arguments); known
  arguments behave as before.
- Each fix has a test. `docs/` is updated to match in the same PR.

## Affected users and systems

Every MCP client of the public and private servers; the extract worker.
Config validation (`src/config.rs`) and the module assertions
(`nix/config.nix`) get stricter: a root, exclusion or state-dir path with
control or invisible characters is rejected. Without this, an unsafe root
path would appear in every result under that root and in `status`.

## Constraints

- Smallest correct change per gap; no new dependencies.
- No change to stored data format that forces a reindex unless the spec
  says why.
- Fail closed: if a path cannot be returned safely, leave it out rather than
  return it raw.
- Existing tests and `nix flake check` stay green.
