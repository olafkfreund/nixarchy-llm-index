# Intent: nixarchy-llm-index, a local file index for LLM agents on NixOS

## Problem

LLM agents on a Linux machine (Claude Code, Codex, Antigravity, Open WebUI and
others) can find files by name with `rg`, `fd` and globs. They cannot find a
document by what it says, by when it changed, or inside formats they cannot
grep: PDF, office files, spreadsheets, slides, scanned pages and images. A
plain-language request such as "use the document from X last week, reference
document Y, then draft Z" fails unless the user first finds the files by hand.

The gap is wider than one machine:

- No shared index. Each agent builds its own, or none has one.
- No control over which documents reach a cloud model. Any text a
  cloud-backed agent retrieves is sent to its provider.
- Source code across many git repositories is searchable only per repo and
  per tool.
- Mounted network folders (NFS, SMB/CIFS, sshfs, rclone) are invisible to the
  file-change events local tools rely on, so anything that indexes them goes
  stale or hangs when the share drops.
- Existing tools each cover part of this (code-only search, markdown-only
  search, heavy RAG stacks needing a GPU or a Python ML stack, or cloud
  parsing). None of them is a NixOS-native package that a laptop can run.

The first user is the owner's fleet (`olafkfreund/nixos_config#2858`), but the
problem is the same for any NixOS or Home Manager user.

## Proposed outcome

A public, reusable Nix flake that any NixOS or Home Manager user can enable
with a few lines of configuration. When it is enabled:

- **Agents can find documents.** Any MCP-capable agent the user registers can
  search by meaning, by title or path, by folder, by file type and by
  modification date ("changed last week" means file mtime). Each hit gives
  the path, the date and the relevant passage, and the agent can read more of
  that document on request. Agents combine hits with their other tools (mail,
  calendar, tasks); this project builds no mail or task integration.
- **All kinds of files.** Markdown and text, PDF including scanned pages,
  office formats (word processing, spreadsheets, slides), images (text found
  by OCR), and source code from git repositories, chunked by code structure
  and following the repository's ignore rules.
- **Local and network folders.** Folders on local disks and on mounted
  network shares are indexed. A share that is slow, offline or unmounted never
  hangs the search service or the host, never causes its documents to be
  dropped from the index as if deleted, and is reported as stale or offline in
  results.
- **Stays current by itself.** Local changes appear within 5 minutes. Network
  folders are rescanned on a schedule the user sets. No manual step.
- **Light by default.** Installs and works on a laptop with no GPU and no
  Ollama. Keyword search works with no model at all. The default semantic
  model runs on CPU. Background indexing yields to the user's work and can
  pause on battery. Heavier local models or an Ollama / OpenAI-compatible
  embedding endpoint are opt-in.
- **Self-contained.** The flake ships every dependency it needs, including
  default model files. Nothing is downloaded at first run, and it works
  offline.
- **Tiers.** The user marks folders public or private. A folder nobody has
  classified is private. Cloud-backed agents can reach the public tier only;
  private passages, titles, paths and counts are invisible to them. Clients
  running local model weights only can reach both. Some paths are never
  indexed: credentials, keys, `.env` files, agent and browser profiles, by
  default.
- **Nothing leaves the machine to build the index.** Text extraction, OCR and
  the default embeddings run locally.
- **Agents know it exists.** The project documents (and can generate) the
  `AGENTS.md` / `CLAUDE.md` lines that tell agents when to use it, and
  declarative MCP registration for common agents.
- **Proven.** Acceptance tests run in the flake's checks: a fixture tree with
  documents of each type, a git repo, a simulated network folder that goes
  offline, and both tiers. Scripted queries return the expected files from the
  right tier, a cloud-tier client gets nothing private, and an offline share
  neither hangs the test nor deletes its entries.

## Threat model

The project prevents **accidental disclosure through retrieval**: a
cooperative agent searching the public tier never receives private text. It
does not contain an agent that deliberately reads files directly; that is the
host's job (sandboxing, permissions). The MCP server cannot know where a
client sends results, so tier separation must not depend on a parameter the
client chooses. Indexed text is untrusted: documents and repositories can
contain prompt injection, and the indexer never executes anything found in
what it indexes.

## Affected users and systems

- NixOS users (system module) and Home Manager users, including Home Manager
  on non-NixOS Linux.
- Laptops and small hosts without a GPU, as well as workstations.
- Agents: Claude Code, Codex CLI, Antigravity, Open WebUI, and any other MCP
  client.
- Network filesystems: NFS, SMB/CIFS, sshfs, rclone mounts.
- The owner's fleet (`nixos_config`), which consumes the flake: its own intent
  (#2858) shrinks to enabling the module on p620 and wiring its agents.

## Constraints

- **Lightweight is a requirement, not a goal.** No GPU, no ML framework such
  as PyTorch, and no database server in the default install. The spec must
  state the installed size and the idle and indexing memory, and keep them
  small enough for a laptop.
- No mandatory Ollama or network service. Optional backends are opt-in, and
  the user declares whether each one is local or remote, since a remote
  backend changes what may be embedded.
- The service never writes, moves or deletes the files it indexes.
- The index, its write-ahead logs and caches live on local disk, readable only
  by the owning user (or service), never on a network mount, and are excluded
  from file sync by default.
- Tier separation does not rely on a query parameter: a public-tier client
  has no path to private data.
- Listeners bind to loopback by default; anything else is opt-in and
  authenticated.
- No secret values in the Nix store. Optional remote credentials load at
  runtime from a file.
- The flake follows NixOS conventions: options under one namespace, explicit
  imports, no auto-discovery, system service hardening (`DynamicUser`,
  `ProtectSystem = "strict"`, `NoNewPrivileges`, read-only access to indexed
  roots), user services where user mounts and home folders must be visible.
- Mount options are never changed by the project. Hard NFS mounts can block
  in the kernel; the design must keep the service usable anyway.
- Default models and dependencies carry permissive licences (MIT,
  Apache-2.0, BSD). Anything else is optional and clearly marked.
- x86_64-linux and aarch64-linux.

## Out of scope

- Answer generation, chat UI, rerankers or query-expansion models in the
  default install.
- Mail, calendar or task integration.
- Blocking direct file reads by agents.
- Searching git history (only current working trees).
- Visual search of images by what they show (OCR text only).

   serving its last indexed passages to local clients (marked stale), or hide
   them until it is back?
