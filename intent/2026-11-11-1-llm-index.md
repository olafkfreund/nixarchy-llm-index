# Intent: nixarchy-llm-index, a local file index for LLM agents on NixOS

## Problem

LLM agents on a Linux machine (Claude Code, Codex, Antigravity and other
shell-capable agents) search files with `rg`, `fd` and `find`: exact text,
names and dates. What they lack is one shared, reliable way to find a
document **by meaning** when the wording differs, across every format and
location the user keeps documents in. A plain-language request such as "use
the document from X last week, reference document Y, then draft Z" fails
unless the user first finds the files by hand.

The gaps:

- **Formats `rg` cannot read.** PDF, office files, spreadsheets, slides,
  scanned pages and images hold text that plain grep never sees.
- **No shared index.** Each agent builds its own, or none has one. Chat
  front ends such as Open WebUI keep their own separate document stores.
- **No control over which documents reach a cloud model.** Any text a
  cloud-backed agent retrieves is sent to its provider.
- **Code and documents are searched separately.** Cross-repo code search by
  meaning, alongside documents, needs one more tool per agent.
- **Network folders.** Changes made on a NAS or by another machine are not
  reliably delivered as local file-change events, and a share that drops can
  stall anything that reads it.

Existing tools cover parts of this: full-text desktop indexers (`recoll`,
`localsearch`), code-only semantic search (ck, Semble, VectorCode), markdown
search (qmd), and heavy RAG stacks needing a GPU, a Python ML stack or cloud
parsing. No single NixOS-native package covers meaning and keyword search
across documents and code, with MCP access and privacy tiers, light enough
for a laptop.

The first user is the owner's fleet (`olafkfreund/nixos_config#2858`); the
problem is the same for any NixOS or Home Manager user.

## Proposed outcome

A public, reusable Nix flake. Enabling it takes the module plus a list of
folders; everything else has working defaults. When enabled:

- **Agents find documents.** Any MCP client the user registers can search by
  meaning, by exact words, by title or path, by folder, by file type and by
  modification date ("changed last week" means file mtime). Each hit gives the
  path, the date, the relevant passage and whether the source is current or
  stale, and the agent can read more of that document on request. Agents
  combine hits with their own other tools (mail, calendar, tasks); this
  project builds none of those.
- **Code is first-class.** Searching git working trees returns whole
  functions, classes and definitions with file and line ranges, follows the
  repository's ignore rules, and skips generated and vendored files.
- **Local and network folders.** Local disks and mounted NFS, SMB/CIFS, sshfs
  and rclone shares can all be indexed. A slow, offline or unmounted share
  never blocks search and never blocks indexing of healthy folders. Its
  entries stay in the index marked stale, and are only removed after a later
  complete scan of that share confirms the files are gone.
- **Stays current by itself.** Local edits appear within 5 minutes while
  indexing is not paused, for changes of up to 100 files at a time. Network
  folders are rescanned on a schedule the user sets. Larger batches (an
  initial index, a branch switch, a folder of scans) report progress and
  finish within the throughput bound below.
- **Light by default**, measured on a reference laptop: x86_64, 4 CPU cores,
  8 GB RAM, no GPU, no Ollama.
  - Installed closure of the default package: 500 MB or less, model files
    included.
  - Search service idle memory: 100 MB or less.
  - Indexing memory: 1 GB or less, with a configurable cap.
  - Initial index of 10,000 mixed documents: 2 hours or less.
  - Search works with no GPU and no network service. Indexing can pause on
    battery and run at low priority.
- **Self-contained.** The flake ships every dependency, including default
  model files. Nothing is downloaded at first run; it works offline after
  install.
- **Tiers.**
  - The user marks folders public or private. An unclassified folder is
    private.
  - The user decides which client registrations get private access. A client
    without that grant has no path to private passages, titles, paths or
    counts.
  - A client that can switch between cloud and local models counts as cloud,
    and gets public access only, unless the user registers a separate
    local-only profile of it.
  - Reclassifying a folder from public to private, adding an exclusion, or
    removing a folder takes effect on the next search, whether or not the
    share is mounted. Nothing indexed before still reaches a public-tier
    client.
- **Never indexed, in any tier, by default:** credentials, keys, `.env`
  files, password stores, agent and browser profiles. The user can lift an
  exclusion for the private tier only.
- **Nothing leaves the machine by default.** Extraction, OCR and embeddings
  run locally. An opt-in remote embedding backend may only ever receive
  public-tier content; private content always stays local.
- **Easy agent setup.** Declarative registration for common agents, plus the
  `AGENTS.md` / `CLAUDE.md` lines that tell agents when to use the index.
- **Proven by tests.** The flake's checks prove the outcomes above, including
  both tiers, reclassification, and a network share that goes offline. The
  spec defines the tests.

### Releases

- **v0.1:** Markdown, text, HTML, PDF with a text layer, `.docx`, `.odt`,
  `.xlsx`, `.ods`, `.csv`, source code; local folders and network polling;
  meaning and keyword search with the bundled CPU model; both tiers; NixOS
  module and Home Manager on NixOS; x86_64-linux.
- **v0.2:** OCR for scanned PDFs and images, `.pptx` / `.odp`, battery-aware
  scheduling, opt-in Ollama / OpenAI-compatible embedding backends, Home
  Manager on non-NixOS Linux, aarch64-linux.

## Threat model

The project prevents **accidental disclosure through retrieval**: a
cooperative client without a private grant never receives private text,
including from symlinks, stale entries or reclassified folders. It does not
contain an agent that deliberately reads files directly; that is the host's
job (sandboxing, permissions). The server cannot know where a client sends
results, so private access depends on how the user registered the client,
never on a value the client sends. Indexed content is untrusted: documents and
repositories can carry prompt injection, malformed files and decompression
bombs, and the indexer executes nothing it finds.

## Affected users and systems

- NixOS users (system module) and Home Manager users; Home Manager on
  non-NixOS Linux from v0.2.
- Laptops and small hosts without a GPU, and workstations.
- MCP clients: Claude Code, Codex CLI, Antigravity, Open WebUI and others.
- Network filesystems: NFS, SMB/CIFS, sshfs, rclone.
- The owner's fleet (`nixos_config`): its intent (#2858) shrinks to enabling
  this flake on p620 and registering its agents.

## Constraints

- No GPU, no database server and no network service in the default install.
  Optional backends are opt-in.
- The indexer only reads the folders it indexes; it never writes, moves or
  deletes them.
- Symlinks are never followed out of an indexed folder, and never from a
  public folder into a private or excluded path.
- Each instance belongs to one owner. Its index and caches live on local disk,
  readable only by that owner (or its service account), never on a network
  mount, and are kept out of file sync by default.
- Access to the server is limited to its owner, even on the same host: other
  local users and processes of other users cannot query it. Network listeners
  are off by default; when enabled, they are authenticated.
- Per-file limits on size, decompression ratio and parse or OCR time, so one
  file cannot exhaust memory or stall indexing.
- Mount options are never changed. A dead hard NFS mount can block in the
  kernel; at most one stuck probe per unreachable share is allowed, and the
  rest of the service keeps working.
- The flake builds under pure evaluation with no import-from-derivation, and
  all downloads (including model files) are fixed-output with pinned hashes.
- No secret values in the Nix store. Credentials for optional remote backends
  load at runtime from a file.
- Follow NixOS conventions: one option namespace, explicit imports, hardened
  services with read-only access to indexed folders.
- Licences: no strong copyleft (GPL, AGPL) in the project's own direct
  dependencies or default model weights. Base system libraries (glibc and
  similar) are fine. Copyleft extras are optional and marked.

## Out of scope

- Answer generation, chat UI, rerankers or query-expansion models in the
  default install.
- Mail, calendar or task integration.
- Blocking direct file reads by agents.
- Searching git history (current working trees only).
- Visual search of images by what they show (OCR text only, from v0.2).
- Multi-user shared indexes.
