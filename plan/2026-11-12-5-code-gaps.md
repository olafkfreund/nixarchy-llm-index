# Plan: close three code gaps found while documenting v0.1

Self-contained: a coder can execute this without the intent or spec.

## Decisions carried from the approved spec

- **Unsafe name:** a name with any character `sanitize::is_stripped`
  matches (`src/sanitize.rs:5`), any `char::is_control` character (C0, DEL,
  C1, so newline, tab, ESC), or one that is not valid UTF-8. One helper,
  `sanitize::unsafe_name(&OsStr) -> bool`, next to `is_stripped`, plus
  `unsafe_path(&str) -> bool` (any char unsafe) for already-stored strings.
- **Skip, don't clean:** unsafe entries are not indexed. Cleaning would
  break `get` and could collide two names. No escape encoding.
- **Scan/watch:** `Walker::reason` (`src/worker/scan.rs:261`) returns
  `Some("unsafe_name")` first, before the other reasons. Recursion stops on
  any reason; watcher events call `reason` (`src/worker/watch.rs` ~205);
  `allowed_event` (`scan.rs` ~492) checks each component. No status
  counter, no schema change, no forced reindex: old rows are deleted by
  the next complete scan via `apply_scan` (`src/index/store.rs` ~509).
  `unsafe_name` must not be added to `protects` (`store.rs` ~85).
- **MCP fail closed:** `search` (`hit()`, `src/mcp.rs` ~321), `recent`
  (~510) and `get` (~475) drop any row whose stored path is unsafe; `get`
  on an unsafe path answers like an unknown path ("not found").
- **Config:** `Config::validate` (`src/config.rs:133`) checks root paths,
  exclusion paths and `state_dir` for unsafe characters **first**, before
  any check that interpolates a path, with the fixed message
  `path contains control or invisible characters` (no path in it).
- **Nix:** `nix/config.nix` assertions reject a root, exclusion or
  `stateDir` containing a C0 control or DEL (via `builtins.match`); this is
  narrower than Rust, which stays the authority. `stateDir` gets its first
  assertion.
- **ODS/XLS cells:** a running per-workbook total of
  `height as u64 * width as u64` (saturating, full rectangle) after each
  `worksheet_range`, `ExtractError::TooLarge` once over `limits.max_cells`,
  before `append_range_segments`. Residual stated in docs: calamine 0.38
  loads all ODS/XLS sheets at open, so the initial allocation happens before
  the check; bounded by the 20 MiB cap and the worker `RLIMIT_AS` (4 GiB).
- **Unknown args:** `#[serde(deny_unknown_fields)]` on `SearchArgs`,
  `GetArgs`, `RecentArgs`; `status` takes `Parameters<StatusArgs>` with an
  empty `StatusArgs {}` carrying the same attribute. Omitted `arguments` and
  `{}` stay valid for `status`. `_meta` beside `arguments` stays valid.
- Docs updated in the same PR.

## Steps

1. **Unsafe-name rule (scan/watch).** `src/sanitize.rs`: add `unsafe_name`
   and `unsafe_path` with unit tests (RLO U+202E, tag U+E0041, ZWSP U+200B,
   `\n`, ESC, DEL, U+0085, invalid UTF-8 via `OsStr::from_bytes` → true;
   `notes.md`, `Ünïcödé.md`, `日本語.txt` → false). `src/worker/scan.rs`
   `reason`: first check `unsafe_name(name)` → `Some("unsafe_name")`; unit
   test for a file and a directory. Skipped entries already go out as
   `Message::Skipped` with their reason (`scan.rs` ~560); check that the
   coordinator logs skips at debug level for the existing reasons and that
   `unsafe_name` takes the same path. If skips are not logged at all, add
   nothing and record in this plan that the spec's "logged as the other
   reasons are" means not logged.
   Watcher test: there is no running-worker harness in `watch.rs` tests
   (only a watch-attach test near line 296). Grep `tests/` for
   `WatchReady` and reuse any existing route; otherwise start
   `llm-index worker --role watch` as a child the way `tests/e2e.rs` starts
   processes, wait for `WatchReady`, then create `bad\u{202e}dir/ok.md`
   **and** a positive control `good/ok.md`, wait past the 2 s debounce with
   a bounded timeout (e.g. 10 s), expect an event for `good/ok.md` and none
   for the unsafe one, then shut down by closing stdin. If no harness can be
   built with reasonable effort, cover it in the e2e test below (index
   running, create both after the first scan) and record that here.
   Store test: a pre-existing row for an unsafe path is deleted after a
   complete scan that skipped it (reuse the `fx`, `extracted`, `scan`
   helpers in `src/index/store.rs` tests).
   End-to-end test (spec requirement): in `tests/e2e.rs`, index a tree
   that holds an RLO-named file and an RLO-named directory with a safe file
   inside; assert neither appears in `search` or `recent`, and a safe
   sibling does.
   → verify: `nix develop -c cargo test --all-features` green.
   Traps: `reason` gets `path`; take the name from `path.file_name()` as
   the existing code does. Do not touch `protects`.

2. **MCP filter + config ordering.** `src/mcp.rs`: skip unsafe paths in
   `hit()` results, `recent` rows and `get` (return the existing not-found
   error). `src/config.rs` `validate`: loop over roots, exclusions and
   `state_dir` with `unsafe_path` before the existing checks; fixed message.
   Tests: store rows with an RLO path directly in a test DB (use
   `Fixture::add` in `tests/mcp.rs`, which fills files, chunks and both FTS
   tables; `state = 'ok'`) → absent from
   `search` and `recent`, `get` says not found; `validate` rejects unsafe
   root, exclusion and `state_dir`, and two duplicate unsafe roots give the
   unsafe message without the path; the private MCP server started on an
   unsafe config returns an error that contains no path.
   → verify: tests green.
   Traps: public server errors are already generic; the private-server test
   is the one that matters.

3. **Nix assertions.** `nix/config.nix` `assertions`: one entry rejecting
   control characters (C0 or DEL) in root paths, exclusions and `stateDir`.
   A pattern such as `builtins.match ".*[[:cntrl:]].*" p != null` — check
   that `[[:cntrl:]]` works in Nix's regex (POSIX ERE); if not, list the
   bytes. `nix/checks/modules.nix`: three failing cases (root, exclusion,
   `stateDir`), each asserting the message.
   → verify: `nix build .#checks.x86_64-linux.modules -L`.
   Traps: a literal control char in a Nix string needs an escape (`"\t"`,
   `"\n"`; for ESC use `builtins.fromJSON "\"\\u001b\""`).
