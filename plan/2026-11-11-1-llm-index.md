# Plan: nixarchy-llm-index v0.1

Builds v0.1 of `llm-index` on branch `feat/1-llm-index-v0.1` (from
`docs/1-llm-index-intent` once merged, or from it directly). The repository
holds only `LICENSE`, `README.md`, `.gitignore`, `.markdownlint.yaml`,
`intent/`, `spec/`; every code file below is new.

## Approved decisions (self-contained)

Everything a step needs; the spec is the long form.

### Product

- One Rust binary `llm-index`, subcommands `index` (long-running service, sole
  DB writer), `worker` (short-lived or watcher child of `index`), `mcp --tier
  public|private` (stdio, spawned per client session, read-only), `status`
  (CLI, reads DBs). x86_64-linux only. MIT.
- v0.1 formats: Markdown, plain text, HTML, PDF text layer, `.docx`, `.odt`,
  `.xlsx`, `.ods`, `.xls`, `.csv`, source code. No OCR, no `.pptx`.
- Bounds on the reference laptop (x86_64, 4 cores, 8 GB, no GPU): closure
  ≤ 500 MB incl. model; `mcp` RSS ≤ 100 MB idle and warm; indexing service
  cgroup `memory.peak` ≤ 1 GB; 10,000 mixed files ≤ 2 h; 100 local edits
  searchable ≤ 5 min.

### Dependencies

| Sandbox | `landlock` |
| Watch | `inotify` (non-recursive) |
| Walk | `ignore` 0.4 |
| Code | `tree-sitter` + grammars Rust, Python, Go, JavaScript, TypeScript, Nix, C, C++, Java, Bash, TOML, YAML, JSON |
| Text | `text-splitter` 0.33 |
| PDF | `pdfium-render` 0.9 against nixpkgs `pdfium` with V8 and XFA off |
| Sheets | `calamine` 0.38; `csv` 1.x |

No GPU, ONNX, Ollama, database server, network listener. No GPL in direct
dependencies.

### Storage

- State dir: `$XDG_STATE_HOME/llm-index/` (HM, created by `index`) or
  `/var/lib/llm-index/<owner>/` (NixOS, `StateDirectory=`); option `stateDir`
  / config `state_dir`. Mode 0700, files 0600. `index` refuses to start if
  the state dir is on a network/FUSE fs (`statfs`) or a parent has
  `.stfolder`, `.sync`, `.dropbox`, `.nextcloudsync.log` or `.sync_*.db`.
  State dir is a built-in exclusion. Writes `CACHEDIR.TAG`.
- `public.db` and `private.db`, same schema, each file in exactly one.
  `mcp --tier public` opens only `public.db`, with no flag, path or tool that
  reaches `private.db`. `mcp --tier private` opens both.
- Schema per DB:
  - `roots(name, path, kind, share_id, state, reason, last_scan, queued,
    done, skipped_symlinks)`. **`public.db.roots` holds only public roots;
    private roots, their names, paths and any clear-text error path live
    only in `private.db`.**
  - `files(id, root_id, relpath, abspath, title, type, size, mtime_ns, blake3,
    state, reason)`, unique `(root_id, relpath)`. `root_id` is the
    configured root **name**, never a device or inode number.
  - `chunks(id, file_id, ord, kind, start, end, decl_start, decl_end,
    heading_or_symbol, text, vec BLOB(512))`
  - `chunks_fts` (FTS5, chunk text), `files_fts` (FTS5, title + path); both
    `tokenize = "unicode61 remove_diacritics 2"`, **no porter**
  - `embed_cache(input_blake3 PRIMARY KEY, vector)`; key = BLAKE3(model_rev
    ‖ full embedding input incl. path/symbol prefix)
  - `validated(path_blake3, config_error)` (both DBs; hashes only)
  - `config_errors(path, reason)`: **`private.db` only**, clear-text paths
    that failed validation, read by the private server and `status`
  - `meta(model_rev, schema_version)`
  - WAL mode; `index` writes, others read.
- Embedding input = `"{relpath}\n{symbol or heading or ''}\n{chunk text}"`
  (one shared function, `embed::input()`).
- Vectors: L2-normalised, ×127, round, clamp to int8. Similarity =
  `dot_i8(a, b)` Rust scalar SQL function. Order **DESC**.
- Titles: Markdown front-matter `title` or first H1; HTML `<title>`; PDF
  `Title` else first text line; docx/odt `dc:title` else first heading;
  sheets and code: filename.
- Roots canonical: absolute, no symlink component. `abspath = root path +
  relpath`. Nested roots: parent walk skips any directory that is another
  root.

### Search and tools

- `search(query, mode=hybrid|words|meaning, field=any|title|path, folder?,
  type?, after?, before?, limit?)`. `folder` is an absolute path prefix
  (component-wise); `type` is the file type (`pdf`, `docx`, `code`, …);
  `after` / `before` compare file `mtime`; `limit` default 10, max 50. Words = whole tokens, case/diacritic
  insensitive, `"…"` phrases. `title`/`path` search `files_fts`, one hit per
  file.
- Eligibility (SQL filters + `visible()`) before both legs. Words: BM25 over
  both FTS tables. Meaning: `ORDER BY dot_i8(vec, ?) DESC LIMIT`. RRF k=60.
  Private server: legs per DB; meaning merged by similarity; the two words
  lists enter RRF separately.
- Hit: `path, title, mtime, type, tier (private only), stale, lines
  (code: decl_start–decl_end) | page | sheet+rows, symbol|heading, passage
  ≤ 800 chars` (title/path hits: first chunk).
- `get(path, start?, end?, sheet?)`: pages (PDF), rows (sheets), lines
  (rest); ≤ 20,000 chars per call plus `next`. `recent(days, folder?,
  type?)`: files whose `mtime` is within `days`, newest first, with path,
  title, mtime, type, stale. `status()`: per visible root its name, state
  (`ok`, `offline`, `degraded`, `config_error`), reason, last scan, queued /
  done counts, file and chunk counts, skipped symlinks; sandbox state; DB
  sizes. All `readOnlyHint`. Passages wrapped as untrusted with
  path; strip Unicode tag, bidi-override, zero-width chars at ingest.
- `mcp` memory: parse safetensors header once; `pread` each query token's
  2 KB row; never map or load the matrix.

### Authorization

- `visible(abspath) -> public|private|none`, a Rust scalar SQL function in
  every query's `WHERE`, each tool call in one read transaction. Strings
  only, never filesystem access: longest root whose path is a component-wise
  prefix gives the tier; no root → none; user exclusion or built-in denylist
  (lifts only for private roots) → none; root `config_error` → none.
- Re-read `config.toml` on mtime/inode change. Missing/invalid config → every
  tool errors (fail closed, no last-good fallback). Exclusions outside every
  root make config invalid.
- Validation (indexer, in workers under share rules): longest existing prefix
  of each root/exclusion path opened with `openat2(RESOLVE_NO_SYMLINKS)`;
  re-validated each scan of its root; stores BLAKE3 of validated path strings
  and a `config_error` flag (`ELOOP`) in `public.db`.
- Public server: removals and public→private apply at once. A newly added
  root or exclusion not yet validated, or `config_error`, closes **every
  public tool** with the generic error `index configuration is being
  checked` (no path). Owner decision: fail closed even when the share is
  hung. Private server applies new rules by string at once, never closes;
  it and `status` name the path.
- Public `status` lists only public roots.

### Indexing

- Discovery: `ignore` walker with `.gitignore`, `.git/info/exclude`, global
  gitignore, `.llmindexignore`, denylist, user excludes;
  `follow_links(false)`, `same_file_system(true)`. **Never execute `git`.**
- Format dispatch first: extension + magic (`%PDF-`; ZIP with
  `[Content_Types].xml` carrying the matching main-part content type for
  docx/xlsx, or first-member `mimetype` matching
  `application/vnd.oasis.opendocument.text` for odt and `...spreadsheet` for
  ods; 8-byte OLE2 `D0 CF 11 E0 A1 B1 1A E1` for xls); mismatch → skipped
  `mismatch`. CSV after text checks.
- Extraction bounds (`Limits`): `max_text_bytes` = 32 MiB of extracted text per
  file enforced while building output in every extractor
  (`ExtractError::TooLarge`); `max_cells` = 2,000,000 per workbook (for `.xlsx`
  read sheet dimensions via `worksheet_cells_reader(..).dimensions()` and cell
  coordinate bounds before materialising, reject `TooLarge` if `rows*cols >
  max_cells`, and process sheets one at a time with `worksheet_range(name)` —
  never `worksheets()` — propagating each sheet's error; for `.ods` and `.xls`,
  where dimensions are not available up front, cap input file size at 20 MiB
  and rely on `max_text_bytes` while iterating, with any allocation abort in
  `calamine` caught by the worker process boundary and marked `failed` by the
  coordinator); HTML uses iterative traversal with an explicit stack (no
  recursion), max element depth 256 (deeper content ignored), `<title>` only
  from `<head>`, and a 20 MiB input cap before `parse_document`; PDF caps at
  5,000 pages and `max_text_bytes` total and binds only `crate::pdfium_lib()`
  (never `bind_to_system_library()`, failing closed); ODT/DOCX enforce
  `max_text_bytes` inside block/paragraph accumulation (including `<text:s
  text:c=N/>` with `N` clamped to 1024), require Dublin Core namespace
  `http://purl.org/dc/elements/1.1/` via `quick-xml` `NsReader` for `dc:title`,
  and restrict DOCX fallback headings to `Heading1..Heading9` / `Title` or
  `w:outlineLvl` `0..8` (never `Subtitle`); Markdown titles recognise Setext
  H1, strip ATX closing `#` only after whitespace, and support plain, quoted
  and block-scalar (`|` / `>`) YAML front-matter titles; ZIP keeps the 100× /
  500 MB guard classified from its own counters and caps any single XML member
  at 64 MiB (streaming with `quick-xml` from a bounded reader).
- Skip dirs/files: `.git/`, `node_modules/`, `vendor/`, `third_party/`,
  `target/`, `.venv/`, `venv/`, `__pycache__/`, `.direnv/`, `result*`, dirs
  with `CACHEDIR.TAG`, lockfiles, files > 50 MB. Text/code only: binary (NUL
  in first 8 KB or invalid UTF-8), minified (`.js .css .json .map`, mean line
  > 250), generated (`@generated` or `Code generated … DO NOT EDIT` in first
  4 KB).
- Denylist (all tiers; liftable for private only): `.env*`, `*.pem`,
  `*.key`, `id_rsa*`, `id_dsa*`, `id_ecdsa*`, `id_ed25519*`, `*.p12`,
  `*.pfx`, `*.kdbx`, `*.age`, `.netrc`, `.git-credentials`, `.npmrc`,
  `.pypirc`, `.docker/config.json`, `.cargo/credentials*`, `.ssh/`,
  `.gnupg/`, `.password-store/`, `.aws/`, `.azure/`, `.kube/`,
  `.config/gcloud/`, `.config/gh/`, `.config/sops/`,
  `.local/share/keyrings/`, `.claude/`, `.codex/`, `.gemini/`,
  `.antigravity/`, `.config/Antigravity/`, `.mozilla/`, `.thunderbird/`,
  `.config/google-chrome/`, `.config/chromium/`, `.config/BraveSoftware/`,
  `.config/vivaldi/`, `/run/`, `/proc/`, `/sys/`, state dir. Own matcher, not
  gitignore: case-insensitive on the absolute path; leading `/` anchors at
  fs root; any other pattern matches any run of components at any depth
  (as `**/`); trailing `/` = directory and below.
- Open: `openat2(root_fd, relpath, O_RDONLY | O_NOFOLLOW, RESOLVE_BENEATH |
  RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_XDEV)`, `fstat`
  regular file. Root acquired with `openat2(AT_FDCWD, path, O_RDONLY |
  O_DIRECTORY, RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS)` (not `O_PATH`):
  `ELOOP` → `config_error`, `ENOENT`/dead → `offline`.
- Chunking: tree-sitter declarations, siblings packed to ~512 tokens, large
  declarations split with `decl_start/decl_end` on every part; stored text =
  original source; path+symbol prefix only in embedding input. Markdown by
  headings; other text `text-splitter`; PDF by page; sheets by sheet + row
  block.
- **Check order for every extract job** (also jobs queued before a config
  change): re-evaluate exclusions (against validated paths) and the
  denylist on the absolute path, then size, then open with `openat2`. An
  excluded or denied file is never opened.
- Tier routing: longest root; default private. Cross-tier move = delete from
  one DB and insert in the other, **one coordinator transaction per
  database, public delete committed first**.
- Lockfiles skipped: `Cargo.lock`, `package-lock.json`, `yarn.lock`,
  `pnpm-lock.yaml`, `flake.lock`, `poetry.lock`, `Pipfile.lock`,
  `composer.lock`, `Gemfile.lock`, `go.sum`, `uv.lock`.

### Workers, shares, scheduling

- Coordinator never touches a root; JSON lines over a pipe to workers.
  Coordinator threads are capped at 16 in code (a fixed thread set or a
  current-thread runtime; no default multi-thread async pool, whose blocking
  pool could exhaust `TasksMax`).
- Worker invocation: `llm-index worker --config <path> --role
  scan|extract|watch --root <name>` (bound to one root for its life) or
  `--role validate` (no root). Before Landlock the worker reads
  `config.toml` itself (root path, nested root paths, user excludes,
  `lift_builtin`, `max_file_mb`), so messages carry only the job. A
  `validate` worker's Landlock allows read beneath `/` (it only resolves
  path components, never reads file contents) and no write.
- Worker protocol (`src/proto.rs`, one JSON object per line):
  - coordinator → worker: `Scan`, `Extract { relpath, expected_size,
    expected_mtime_ns }`, `Validate { paths }`, `Watch`, `Shutdown`.
  - worker → coordinator: `Progress { entries | bytes }` (single I/O loop:
    after at least 1 s and only when entries or bytes increased; a hung
    syscall produces no progress), `Entry { relpath, size,
    mtime_ns, is_dir }`, `Skipped { relpath, reason }`, `ScanDone { complete:
    bool, identity_before: { share: { fstype, source, mount_root,
    mount_point }, mount_id, submounts: [..] } | null, identity_after:
    same shape }`, `Extracted { relpath, title,
    type, blake3, chunks: [Chunk { ord, kind, start, end, decl_start,
    decl_end, heading_or_symbol, text }] }` (no vectors; the coordinator
    embeds), `Failed { relpath, reason }`,
    `RootError { state: config_error | offline, reason }` before exit on root
    acquisition failure (`ELOOP`, `ENOTDIR`, Landlock unavailable → `config_error`; `ENOENT`,
    `EACCES`, `ESTALE`, `EIO`, timeout → `offline`),
    `Validated { path, result: ok | eloop | pending }`, `WatchEvent {
    relpath, kind, size: Option<u64>, mtime_ns: Option<i64> }` (statx of the
    file through the pinned directory; `None` when gone or not a regular file →
    the coordinator queues a coalesced rescan, otherwise a direct Extract),
    `WatchDegraded { reason }`, `WatchReady` (initial watches in place; ends the
    watcher's setup progress timeout).
  - A scan counts as complete only on `ScanDone { complete: true }` with
    equal identities; the worker's exit without it is incomplete.
- Worker start order: open `/proc/self/mountinfo` (keep the fd) and read
  the global gitignore once from `$XDG_CONFIG_HOME/git/ignore` (or
  `~/.config/git/ignore`) into an in-memory `ignore::gitignore::Gitignore`
  matcher using plain open (symlinks allowed, regular file only, `O_NONBLOCK`,
  1 MiB cap); `oom_score_adj = 1000`; `RLIMIT_AS = 4 GB`; acquire root fd; apply
  Landlock (handles read + write: read beneath root fd and `/nix/store`, no
  write, best effort rights for the running ABI, refuse to start if filesystem
  restriction is unenforced, ABI ≥ 4 no TCP bind or connect); then take jobs.
  Single-threaded. Mount checks
  re-read the kept fd from offset 0.
- Scanner and watcher traverse only by fd relative `openat2` from the acquired
  root fd (`O_RDONLY | O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC`, `RESOLVE_BENEATH |
  RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_XDEV`). `rustix::fs::Dir`
  reads entries; `statx(dirfd, name, AT_SYMLINK_NOFOLLOW)` reads metadata.
  A refused mount, including a same-device bind mount, is `Skipped { reason:
  "mount" }`. Dot directories are eligible. Per-entry `statx`, open or readdir errors send
  `Skipped { relpath, reason: errno }` and traversal continues; `EACCES` and
  `ENOENT` on an entry preserve scan completeness, while `EIO`, `ESTALE`, root
  errors and mount identity changes make `complete: false`.
  No path string is used for I/O
  after root acquisition, except pinned `/proc/self/fd/<n>/.` watcher handles
  (`/.` makes `IN_DONT_FOLLOW | IN_ONLYDIR` target the directory on Linux).
  Check denylist, excludes, nested roots and skip list before reading a
  directory's ignore files. `.gitignore`, `.ignore`, `.llmindexignore` and
  `.git/info/exclude` (only for a real `.git` directory) are opened beneath
  the root with `O_NONBLOCK`, no symlink or mount crossing, verified regular
  and capped at 1 MiB, then parsed with `GitignoreBuilder::add_line`; never
  follow a `.git` file containing `gitdir:`. Global ignore parse/missing
  errors warn on stderr, never abort. `CACHEDIR.TAG` requires regular-file
  `statx` without symlink following.
- Mount identity unescapes mountinfo octal escapes in point, root, fstype and
  source; retains an empty source field; chooses the longest component-wise
  containing point and the last line on ties. `ScanDone` identity separates
  the share's fstype, source, root and point from mount ID and sorted mount
  points strictly below the root. The coordinator compares `share` with the
  expected share identity; mount ID and submounts are compared only before and
  after the same scan. Compare root fd `STATX_MNT_ID` with the topmost
  mount before and after; mismatch makes the scan incomplete.
- Validation opens the longest existing prefix with `O_PATH | O_NOFOLLOW |
  O_CLOEXEC` and no symlink or magic link resolution. `ELOOP` → `eloop`;
  missing tail, `ENOTDIR` or `EACCES` → `ok`; unresolved errors → `pending`.
- Limits: scan 10 min, extract 30 s; zip members ≤ 100× archive and ≤
  500 MB total. OOM-killed while another worker ran → one solo retry; else
  `failed`, retried only on size/mtime change.
- Watcher worker per local root (outside pool and share rule): watches each
  dir through a temporary pinned `/proc/self/fd/<n>/.` with `IN_ONLYDIR |
  IN_DONT_FOLLOW`, closing the fd after adding the watch and caching each
  watched directory's ignore matcher. On new directories, walk only that
  subtree with the scanner's mount and skip rules. Remove watches on directory
  deletion or move, and poll stdin alongside inotify for `Shutdown`.
  Debounce is a 2 s trailing edge per path;
  any walk, add, queue overflow or read failure sends `WatchDegraded`.
  Progress rule
  while adding watches; trip → kill, abandon, root `degraded`, polled by
  scan workers every 2 min; no new watcher until reaped. `ENOSPC`,
  `IN_Q_OVERFLOW`, watcher failure → `degraded` + immediate reconciliation.
  Daily full reconciliation.
- Coordinator `poll`s `/proc/self/mountinfo`; on change re-derives
  identities and scans roots whose containing mount changed.
- Share identity `(fstype, source, mount root, mount point)` derived by
  string match against `mountinfo` **before** any I/O. Network fstypes: NFS,
  CIFS/SMB2, FUSE (`fuse.sshfs`, `fuse.rclone`, others), `autofs`. Expected
  identity from `share = "…"` or first successful scan. autofs: open root
  (triggers mount), re-derive. Deeper mount replaces recorded identity only
  while the root has **no indexed files**; else any change is a mismatch.
- Network roots: poll every `interval` (default 15 min), `statx` default
  sync mode, `(relpath, size, mtime_ns)`. Mount check before and after scan
  (identity + root fd mount ID); mismatch/unmount → `offline (identity
  mismatch)`, result discarded.
- One live worker per share (scan or extract), counted until `waitpid`
  reaps it; across a re-derive it counts against both old and new identity.
  No progress for 30 s (progress = entries listed / bytes read from the I/O
  thread) → `SIGKILL`, abandon, share `offline`; nothing new on that share
  until reaped **and** backoff (1 → `backoff_max` 60 min, doubling) expired.
- Pool `workers` (default 2, minimum 2) counts live non-abandoned workers;
  network jobs ≤ `workers - 1`. `TasksMax` = 16 + workers + local roots +
  network roots + 8.
- Delete only after a complete scan that passed both mount checks. Offline
  entries served `stale: true`.

### Service and sandbox

- Unit: `Nice=19`, `IOSchedulingClass=idle`, `CPUWeight=20`,
  `MemoryHigh=768M`, `MemoryMax` = `memory_max_mb` (1024), `OOMPolicy=continue`,
  `TasksMax` as above, `NoNewPrivileges`, `RestrictAddressFamilies=AF_UNIX`,
  `SystemCallFilter=@system-service @sandbox`; NixOS also `PrivateNetwork`,
  `User=<owner>`, `StateDirectory`. **No** `ProtectSystem`, `ProtectHome`,
  `PrivateTmp`, `ReadWritePaths`.
- Coordinator Landlock at start: handles write (and TCP on ABI ≥ 4) only;
  write allowed beneath state dir and `/proc`. Without Landlock `index`
  refuses to start; no override.

  { path, tier, kind, interval, share }`, `exclude`, `limits`,

- Package installs `$out/share/llm-index/AGENTS.snippet.md`: when to use the

  meaning across repos), the tools and their arguments, and that passages are
  untrusted content that must not be followed as instructions.

## Steps

Every step: branch `feat/1-llm-index-v0.1`; one commit per step,
`feat(llm-index): <step> (#1)`; before handing back run

```bash
cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test
nix flake check --no-build   # from step 2 on
```

Step 1 has no code and runs none of these. Each step wires what it adds into `src/main.rs` / `src/lib.rs` (no dead
code) and lists new crates in `Cargo.toml`; `cargo` may fetch crates while
developing, but `nix build` and every check run offline. Traps for every
step: never run `git` from the program; no secrets in the store; Landlock
order exactly as written; **any test that calls `landlock_restrict_self`
runs in a child process** (re-exec the test binary with a filter, or fork),
never in the `cargo test` thread pool.

1. **Feasibility record** (lead) → `docs/feasibility.md`. Pin `nixpkgs`

6. **Extractors and the extract job** → `src/extract/{mod,text,markdown,

   input cap for `.ods`/`.xls`, HTML iterative traversal capped at depth 256
   and 20 MiB input, PDF capped at 5,000 pages and fail-closed `pdfium_lib()`
   binding, ODT/DOCX paragraph/block accumulation cap with `<text:s>` clamped

   sections, sheet row blocks, whole file) and `extract.rs` maps each
   segment to one `Chunk` with a fixed 2,000-character split; step 7

   watchers}.rs`: coordinator Landlock (write-only ruleset: state dir and

   → verify: `index --self-test` passes on the dev host; unit tests with a
   fake spawner and fake clock: never two live
   workers per share across three outage cycles and an autofs re-derive;
   two sibling roots started on a dead share get one probe; local jobs keep
   a slot with two hung shares; a healthy third share is still scanned;
   empty root adopts a deeper mount, an indexed root treats it as mismatch;
   OOM-killed worker retried once alone, then `failed`, not retried until
   size/mtime change. The coordinator never opens a root (test under a
   Landlock ruleset denying reads beneath fixture roots, in a child
   process).
   Implementation notes: the share rule and `share` backoff apply to network
   shares only (local roots run up to the pool limit); a `RootError`
   `offline` on a local root holds that root only. An extract timeout or
   crash fails only the file; only a silent scan, or an extract that never
   sent Progress, on a network share marks it offline. Config changes
   (inode/mtime) retire all workers (Shutdown, SIGKILL after 5 s) and queued
   extracts are re-checked against the new config before dispatch; a change of
   roots or limits exits so the service manager restarts it. `index --self-test`
   loads the config for `state_dir`, builds its fixture inside it, and runs
   hidden worker roles `selftest-scan` / `selftest-extract`.
   The expected share identity is persisted through the `Sink` (step 9 stores it
   in `roots.share_id`); an unrecorded identity is adopted only by an empty root
   or a matching `share` setting, and a root recorded on a network share stays
   network (offline) when that share is not mounted. No new work starts on a
   root while one of its workers is abandoned and unreaped. `index` refuses to
   start with `config.toml` on a network/FUSE fstype and does `chdir("/")`.

## Rollback

repository changes. Roll back by not merging, or `git revert` of the merge on
